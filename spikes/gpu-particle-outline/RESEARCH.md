# 研究：GPU 粒子 + 程序化纹理 + 多段线轮廓 的像素角色方案

## 结论先行

**可行，定位是「渲染分支」，不替代现有烘焙管线。** 原型（同目录 `index.html`）用一个
instanced draw call 画完一个 14 部件的小人：quad 即部件，片元里算多段线 SDF 轮廓、
程序化 pattern、调色板量化、运动驱动 rim/glint；骨骼在 CPU 算每部件位姿，斗篷/羽饰走
弹簧滞后。方案的价值在**程序化变体**（换 pattern/调色板 = 换装，零新增美术）与
**逐帧重算的光效**（rim/glint 随角速度变，烘焙帧做不到）；代价是**位图级细节表达不了**
（面部、复杂服饰纹样、手指——矢量多段线的信息量上限明确）。

本地打开：任意静态服务器（或直接双击，脚本无模块导入）打开 `index.html`；
纯逻辑校验：`node verify.mjs`（轮廓编译/打包/排序/量化，全过）。

## 对照方案八节的覆盖情况

| 节 | 内容 | 原型状态 |
|---|---|---|
| §1 数据模型 | Element ≈ 实例属性 17 float：pos/size/rot/pivot + outline/pattern/paletteBase/seed + patternParam + motion | ✓ |
| §2 轮廓 | logo/turtle 指令编译为线段表（Float32 数据纹理）；片元 sdSegment 循环 + `step` 硬边（discard） | ✓（MAX_OUTLINES 8、MAX_SEG 32） |
| §3 Pattern | 条纹/棋盘/噪点/鳞片/金属渐变 5 类；输出调色板档位而非连续色；8 家族 × 8 档查表 | ✓ |
| §4 运动光效 | SDF 梯度伪法线 → rim 阈值化 1 档；glint = 高光向 × 噪声闪点 × 角速度（挥剑越快越闪） | ✓ |
| §5 像素完美 | 位置整数吸附、角度量化 22.5°（可关）、alpha test 无 blending、layer 排序单次绘制 | 部分：轮廓预扩张/接缝处理未做 |
| §6 骨骼结合 | CPU 小骨骼算主体位姿（§6-1）；斗篷三段弹簧链 + 羽饰摆动（§6-2）；跑步时斗篷条纹按状态滚动 | ✓ |
| §7 性能 | instancing 合批 1 draw call；线段/参数走纹理；无 CPU 回读 | 部分：LOD、复杂 pattern 图集缓存未做 |
| §8 最小路径 | 已走到第 4 步（多部件 + 骨骼/状态机）；第 5 步饰品已含（斗篷/羽饰/宝石），图集缓存未做 | ✓/部分 |

## 与 pixelmorpher 现管线的关系

现管线（3D 烘焙精灵 → CPU 逐像素合成）与本分支是互补关系：

- **现管线强在**：烘焙精灵携带全部位图信息——面部、贴图、复杂轮廓天然保真。
- **本分支强在**：部件是「轮廓 + pattern + 调色板」的程序化描述，换装/变体只换参数；
  光效活在片元里随运动逐帧变；旋转是真旋转（像素风靠量化压抖动），不需 26 向烘焙。
- **可复用的上层**：节点层级、IK、蓝图、关键帧/状态机产出的正是 Element 的运动字段
  （pos/rot/scale/motion/state）——若立项，接入点是把渲染后端从「精灵合成」换成
  「Element 流」，上层动画系统不动。
- **最大未知数**：轮廓来源。原型轮廓是手工 8 段多边形；真实角色要从现有精灵 alpha
  自动提取（轮廓追踪 → 多边形简化 → 线段表），保真度与段数成本没有数据，下一步实验②。

## 风险与未验证

1. **片元成本随段数线性涨**：原型每像素跑 3 次全轮廓循环（SDF 本值 + 梯度两 tap）。
   段数 8 时便宜；真实轮廓 32–64 段时低分辨率可接受、移动端吃紧。生产解法是 §2 的
   备选路线——离线把轮廓烘焙成局部 SDF 纹理，片元单采样（梯度也可预存），原型未做。
2. **旋转爬行**：位置吸附 + 角度量化压住了平移抖动，旋转中轮廓边缘仍会逐帧爬行；
   像素风可接受程度需真机主观判断，退路是多方向预烘焙帧（回到现管线思路）。
3. **接缝**：相邻部件各自描边，重叠处靠 layer 硬盖；拐角可能露 1px 底色，未系统处理
   （方案 §5 的轮廓预扩张 1px 是候选解）。
4. **GLSL 未在本地编译**：本机无 GPU/WebGL 环境，着色器只做了括号平衡与人工审查；
   打开页面即验证（编译失败会在控制台抛出 info log）。纯逻辑部分已由 verify.mjs 覆盖。
5. 远近侧部件未做明暗区分（原型同调色板），生产需给远侧单独压暗一档。

## 下一步实验（按序）

1. **SDF 纹理化**：轮廓 → 离线 SDF 图集，片元改单采样 + 预存梯度，测段数上限与成本曲线。
2. **轮廓自动提取**：拿现有烘焙精灵的 alpha 做追踪 + 简化，量化「段数 vs 保真度」。
3. **接现有动画数据**：用一个真实角色的节点/IK 输出驱动 Element 流，验证上层复用度。
4. **接缝策略**：轮廓外扩与同层合并的对比实验。
