# 研究：GPU 粒子 + 程序化纹理 + 多段线轮廓 的像素角色方案

## 结论先行

**可行，定位是「渲染分支」，不替代现有烘焙管线。** 原型（同目录 `index.html`）用一个
instanced draw call 画完一个 14 部件的小人。两条架构口径（已经过两轮纠正，是本研究
的核心结论）：

1. **SDF 只是生成 mask 的中间工具，不是渲染管线。** 距离场只在烘焙期出现：覆盖由点在
   多边形内判定，距离场产边带掩码与梯度方向掩码；产物是离散像素 mask（图集）。
   运行时片元只采样纹理，逐像素成本 O(1)，与线段数无关——描边/rim/光照都不逐像素算 SDF。
2. **pattern 是模式语言，不是图案。** 每个部件的外观是一段 pattern 程序：层 = mask 原语
   （inside/edge/band/bands/checker/noise/gradLt/facing）× 目标档位，按序覆盖；
   光照、描边、rim、表面都从**枚举的常见形式**里组合（见下表），烘焙期编译进 mask。
   运行时不求值 pattern、不做连续光照公式——改外观 = 改程序组合，不改着色器。

原型本地打开：任意静态服务器（或直接双击，脚本无模块导入）打开 `index.html`；
纯逻辑校验：`node verify.mjs`（18 项全过）。

## pattern 语言：枚举形式目录（原型已实现 `F.*`）

| 类别 | 形式 | 说明 |
|---|---|---|
| 光照 | `lightFlat(slot)` | 平涂 |
| 光照 | `lightGradY([上,中,下])` / `lightGradX([左,中,右])` | 三档量化渐变 |
| 描边 | `outlineDark(w)` | 边缘带写最暗档 |
| rim | `rim(deg, slot, w, tol)` | 距离场梯度朝向 ≈ deg 的边缘带写高光档（左上光时背光缘 ≈ −135°） |
| glint | `glintFace(deg, tol)` | 迎光面写 G 候选通道；运行时只在候选区按噪声 × 角速度点亮 |
| 表面 | `stripes / checker / speckle / scales` | 条纹/棋盘/噪点/鳞片压暗带 |

部件程序示例（躯干铠甲）：`lightGradY([3,2,1]) → glintFace(45°) → rim(-135°) → outlineDark()`，
后层覆盖先层。全部输出落到 8 档调色板索引，无连续色。

## 与 pixelmorpher 现管线的关系

- **现管线强在**：烘焙精灵携带全部位图信息——面部、贴图、复杂轮廓天然保真。
- **本分支强在**：部件是「轮廓 + pattern 程序 + 调色板」的程序化描述，换装/变体只换
  程序与调色板；旋转是真旋转（像素风靠量化压抖动），不需 26 向烘焙。
- **可复用的上层**：节点层级、IK、蓝图、关键帧/状态机产出的正是 Element 的运动字段
  （pos/rot/motion/state）——若立项，接入点是把渲染后端换成「Element 流」，上层动画系统不动。
- **最大未知数**：轮廓来源。原型轮廓是手工多边形；真实角色要从现有精灵 alpha 自动提取
  （轮廓追踪 → 多边形简化 → 线段表），保真度与段数没有数据，下一步实验①。

## 风险与开放项

1. **mask 分辨率即烘焙分辨率**：元素放大只能最近邻（像素风可接受）；缩小采样会丢档位细节。
2. **光照是离散形式**：改光向 = 改 rim/glint 形式的 deg 参数重烘 mask，不是实时光照——
   这是枚举口径的固有取舍，换来的是风格可控与运行时零光照成本。
3. **pattern 动效**：烘焙口径下条纹滚动这类时间型 pattern 需要相位变体（一程序多烘几相位）
   或保留一层运行时求值——两者取舍未定，列为开放项（原型已去掉滚动以守口径）。
4. **旋转爬行**：mask 随 quad 旋转、最近邻采样，边缘会逐帧爬行；可接受程度需真机主观
   判断，退路是多方向预烘焙帧（回到现管线思路）。
5. **接缝**：相邻部件各自描边，重叠处靠 layer 硬盖；拐角可能露 1px 底色，未系统处理。
6. **GLSL 未在本地编译**：本机无 GPU/WebGL 环境，着色器只做了人工审查；打开页面即验证
   （编译失败控制台会抛 info log）。纯逻辑部分已由 verify.mjs 覆盖。

## 下一步实验（按序）

1. **轮廓自动提取**：拿现有烘焙精灵的 alpha 做追踪 + 简化，量化「段数 vs 保真度」——立项关键实验。
2. **接现有动画数据**：用一个真实角色的节点/IK 输出驱动 Element 流，验证上层复用度。
3. **pattern 相位变体**：同一程序多相位烘焙的成本与切换观感（解决开放项 3）。
4. **接缝策略**：轮廓外扩与同层合并的对比实验。

## 附录：与「参数化像素角色·修正版」的对照（2026-10-22）

另一实现走的是不同赌注：**参数化角色模型**——部件 = 解析图元（圆角矩形/椭圆/胶囊）
+ 4 个枚举槽（LIGHT/OUTLINE/RIM/GLINT，片元里邻居占据判定）+ 4 色调色板，
Three.js 整屏低清（180p）屏幕空间求值。本 spike 是**资产管线**赌注（轮廓+程序→mask）。

| 维度 | 修正版（参数化模型） | 本 spike（mask 管线） |
|---|---|---|
| 轮廓 | 3 图元，全凸形——凹形/尖角/孔洞无解，多部件拼贴 | 任意多边形可凹，留精灵 alpha 提取通路 |
| pattern 组合 | 槽位组合（四枚举笛卡尔积），无表面纹理层 | 层组合（多层按序覆盖），含条纹/棋盘/噪点/鳞片 |
| 光照实现 | 邻居占据（上邻居空=亮边），最字面的枚举形式 | 烘焙期 facing/band 掩码 |
| 像素格 | **全局统一**（整屏低清+屏幕空间求值） | 部件各自吸附，格不统一 |
| 方向 | **8 方向变体推导**（base+东向+镜像/对角共享）+ 方向遮挡排序 | 单朝向+真旋转，与方向资产模型不合 |
| 像素身份 | **语义表**（部件/变体/格→dof/约束）+ 点击查询，编辑器钩子 | 无 |
| 服装 | 槽位覆盖 pal/size/圆角、null 隐藏 | 换程序+调色板，无槽位/隐藏语义 |
| 出色 | rim/glint 用 mix 向白，出调色板外色 | 档位制，只出调色板色 |
| 片元成本 | 5 次形状求值/像素（低清下无感） | O(1) 采样，与形状复杂度无关 |
| 「烘焙」 | 指动画曲线烘焙（100 桶插值），与 mask 烘焙同名异物 | mask 烘焙 |

**可收编的形式**：`LIGHT.BACK`（逆光）、`OUTLINE.DROP / TOP_ONLY`、`RIM.SCAN`（时间扫描带）、`GLINT.EDGE_FLOW`。

**合流方向（若立项）**：骨架取修正版（参数化部件 + 变体推导 + 方向排序 + 语义表 +
全局格渲染），shape 扩成「图元 ∪ 多边形轮廓（mask 化）」，pattern 在枚举槽位下补层
语言，出色改回档位制。

## 合流版 v2（2026-10-22 拍板并落地，原型已替换为 index.html 合流版）

与参数化版对照后定案的合流架构，原型已按此重写（verify 32 项全过）：

- **骨架取参数化版**：参数化部件、变体推导（base+东向+镜像/对角共享）、方向遮挡排序、
  稀疏语义表（像素身份，点击查询与渲染同源于烘焙瓦片）、全局格渲染（整屏低清 180p +
  屏幕空间求值）、服装槽位、动画曲线烘焙与运动 rim/glint 增量。
- **shape = 图元 ∪ 多边形轮廓，统一 mask 化**：圆角矩形/椭圆/胶囊与多边形（turtle 折线）
  都在加载期经同一 `compileTile` 烘焙成同一种瓦片（R=表面档位/254 外环/255 外、
  G=glint 候选），运行时一条采样路径、片元 O(1)；距离场仍只在烘焙期产边带/方向掩码。
  图元保住参数化版的尺寸/圆角可调，多边形补上凹形/尖角表达力（斗篷、剑为多边形部件）。
- **pattern 两级**：层语言在下管「面」（层程序烘焙每像素基础档位：渐变/条纹/棋盘/
  噪点/鳞片）；枚举槽位在上管「边与光」（LIGHT/OUTLINE/RIM/GLINT 运行时按邻居占据
  以枚举形式调制：LIGHT 只动 1..3 档、RIM/GLINT 写高光档 4、OUTLINE 写 0 档）。
- **出色改回档位制**：调色板 = 家族 × 8 档纹理，所有出色查表；参数化版的 rim/glint
  强度（mix 量）改为哈希门概率，绝不产生调色板外颜色。
- **对参数化版的两处修正**：①镜像改为在合并后的完整参数上统一施加一次——其原链条
  只翻变体覆盖项，base 的 pivot 与多边形轮廓在西向会翻错（图元对称所以它没暴露）；
  ②CPU 命中测试直接读烘焙瓦片，与片元同一数据源，不再维护一份同构形状函数。

保留的开放项：轮廓自动提取（alpha→多边形）仍是关键实验；pattern 相位变体未做；
旋转时瓦片采样爬行未评估；GLSL 仍未在本地编译（无 WebGL 环境），打开页面即验。

## v3：程序化动画运行时形态（2026-10-22 按定性与 UI 接线方案落地）

定性（经三轮纠正）：导出物是**程序化动画运行时**——不导帧、不导轨道。v3 已按此重构：

- **程序化引擎泛化**：删掉按部件 key 硬编码的三态动画与动画烘焙开关。姿态由
  `computeProceduralPose(behavior, input, state, dt)` 合成：behavior = 步态参数 +
  部件角色表（legL/legR/foot/arm/torso/head/spring）+ 弹簧配置 + 持握跟随（attach，
  剑跟随 armR 带弹簧滞后）；宿主只喂 moveX/grounded/t。换角色只换数据表。
- **作者型表演挂蓝图**：表演 = { 图数据, 触发键, duration, 包络, mode, 部件掩码 }；
  运行时带小求值器（方言：time/const/curve/math/sin/transform，节点 enabled 短路，
  拓扑求值）。合成口径两存：override 按包络权重接管、add 加算（图根部开关）；
  掩码外部件程序化照旧（斩击时腿继续跑）。实例流效果落地一项：表演残影
  （afterimage：历史实例重发、档位压暗，ghost 位走实例 param.w）。
- **bump 收编**：bump 是枚举的几种连续光照公式——以距离场为伪高度图、烘焙期跑公式、
  两阈值量化成三档写入瓦片（F.bump：dome/top/side/edge），躯干默认程序已换穹光。
- **UI 按主系统接线方案成形**（页面右侧面板即接线原型）：①部件外观（部件选择 +
  调色板/表面预设/四枚举槽位/圆角，改即 dataRev 重烘图集）；②行为（步态滑杆 +
  部件角色表，剑行显示「持握跟随」）；③表演清单（模式切换/触发按钮）；④导出
  （character-runtime.json：调色板/部件/服装/行为/表演全量数据；运行时本体即本页）。
- 与主系统的距离：产品接线（RigPanel 真字段、蓝图编辑器产图、导出对话框页签）未做，
  本版是研究线的全链验证；合成口径与方言范围已按上文讨论定（方言按相容性划线，
  像素变形类待翻译层）。
