# 钳制锚定研究：指定点到达钳制条件后锚定、角色其余部分反向移动

需求原话：「指定点（节点/节点对/像素/像素对/精灵边缘）由 IK 结算到达所设置钳制高度/目标点/目标范围时，暂时锚定该指定点位置，将角色其他部分反向移动以满足 IK 结算结果」；追加：「运行时包自动运用于所有地面和平台」。

## 结论先行

锚定的语义（2026-10-28 用户纠正定版）：**锚定 = 指定点全位置冻结、不滑动；IK 结算照常出位姿，锚点被结算带走多少，整角色（身体）就反向横移多少把它送回冻结位，结算位姿本身（相对姿态）不动。** 先前研究稿「锚在面上、沿面滑动」的读法已被用户否掉作废。

机制定式：每帧在平结算位上求值触发；触发成立的瞬间把锚点位**冻结**（高度触发 = 当帧结算位投影到高度面后的整位、含 X/Z；目标点 = 目标本身；范围 = 进入点；场景固体 = 接触位投影到顶面后的整位）。生效期间每帧 Δ = 冻结位 − 当帧结算位（多锚硬优先级：最高优先锚独占 Δ），整角色全部节点世界位 += Δ，单遍、无迭代。释放 = 平结算位脱离触发条件。状态只有每锚一条冻结记录，从未生效状态顺序求值结果确定。spike（`spike.mts`，14 条断言全过）已验：落脚冻结、支撑期脚不滑而身体照常过脚（脚目标世界固定时 Δ 只补穿深）、脚被目标拖滑时身体反向横移 −14 精确抵消、抬脚释放、多锚硬优先级、边缘锚平移边界、边缘旋转只掰锚点所在节点、冻结位生效期间恒定。

运行时包侧：包格式已有场景固体（`scene.solids`，AABB 列表），播放器物理已对全部固体统一碰撞；缺的是按指定点的贴合——现只有整角色一刀切的 `localGround`（所有部件最低点 −4px 对世界地面 y=0）。设计：convert 把锚点定义随包发出（部件 + 命名标记/局部点），播放器逐帧求值表演后，把每个指定点对**全部**固体的顶面（地面/平台）做同一套触发/锚定/反移，对绘制原点施加 Δ——不逐个表面著者设置，即「自动运用于所有地面和平台」。此事不能烘焙进 convert 采样：角色位置由宿主运行时驱动，同一表演在任意位置播放，贴合必须在播放器按当帧位置求值。

## 一、指定点：五种来源，统一解析为世界点（对）

锚定的对象在求值时一律落成 1 个或 2 个世界点（点对/边缘 = 有序点对）：

| 来源 | 解析口径 |
|---|---|
| 节点 | 关节世界位（结算后 WorldTransform 的 worldX/Y/Z） |
| 节点对 | 两关节世界位，成段 |
| 像素 | 节点当前精灵上的像素：优先命名标记（`SpriteMark` 的 point 类，`markPointPx` 解析为精灵像素位），或裸坐标；精灵局部 → 节点局部（减 plug）→ 世界 = 节点位 + `applyFrameRotation(帧, 局部偏移, 朝向)`，与子关节偏移同一公式 |
| 像素对 | 两像素同上，成段 |
| 精灵边缘 | 精灵矩形四边之一（plug 相对的两角点）解析为世界段；或由两点标记定义边 |

堆叠件上的像素：摞的合成图有自己的局部空间（摞原点 + 层序），像素点可按合成图坐标解析，世界位走摞的当帧帧——与精灵像素同构，建议二期再开，一期只认普通精灵与节点。

## 二、触发：三种著者触发 + 一种场景自动触发

触发一律在**平结算位**（未施加任何锚定补偿的当帧位姿）上求值——释放判定因此不依赖补偿后位置，不会自锁：

- **钳制高度**：点的世界 Y 越过高度面（编辑器 Y 向下：地面 = Y ≥ 线；天花板反之）。生效帧冻结位 = 当帧结算位投影到该面后的整位（X/Z 一并冻结，**不沿面滑动**）。
- **目标点**：点与目标点距离 ≤ 半径（到达）。冻结位 = 目标点本身。
- **目标范围**：点进入区域（矩形/圆形，可带 Z 区间）。生效帧冻结位 = 进入点的结算位（钳进区域后的位）。
- **场景固体（运行时自动）**：点在某固体顶面的水平跨度内、且点位低于顶面 + 吸附带（或穿入）：触发。冻结位 = 接触位投影到顶面后的整位。全部固体逐个试，取穿深最小/最近者。场景侧预览口径见裁决 4（§七、§十）。

注：冻结是全位置的——脚踩地后身体前倾、脚目标被拖动、根轨横移，都不能让脚滑动半个像素，差额全由身体反向横移吸收（spike A3/A4 两态：脚目标世界固定时腿的重弯自然吸收、身体照常前进；脚被目标拖滑时身体被反移抵消）。

## 三、反向移动：结算后整角色刚性反移（单遍）

- 落点：`computeWorldTransforms`（`src/lib/unified-render.ts` 约 486 行起；现有结构是「FK → 解链覆写（`solveChainIKOverrides` 约 691 行）→ 带覆写重算」）在结算完成后加一段：求值各锚的冻结位与当帧结算位 → Δ（多锚硬优先级）→ **把返回的每个 WorldTransform 的世界位 += Δ**（帧/角度不动）。刚性平移不改相对姿态，IK 结算结果原样保留——这正是「将角色其他部分反向移动以满足 IK 结算结果」的字面实现。必须进 `computeWorldTransforms` 内部：拾取、覆盖层、convert 采样都只认这一个取位出处，进内部才全线同源（与 IK 覆写同理）；在渲染计划层平移会让点选与出图分家。
- 单点锚 Δ 精确（spike A1/A4）；不改写任何链目标——链目标是什么样，结算位姿就是什么样，锚定只做事后整移。先前研究稿「锚定覆盖同点目标再迭代重解」的冲突问题在本定式下不存在（该稿定式已随滑动读法一并作废）。
- 「反移后重解」做成**可设置的选项**（2026-10-28 裁决 2）：锚定条目可开 `resettle` —— 开后在刚性反移之上再重解一遍各链（目标仍是世界量、根已移位），让其他链末端回到各自世界目标，锚点由第二遍 Δ 兜底；默认关（纯刚性反移）。开与关的位姿不同，此项属逐锚著者选择，不做全局默认切换。

## 四、多锚、点对与边缘：平移自由度的边界

- 多锚同帧生效走**硬优先级**（2026-10-28 裁决 7）：全局平移只有一个 Δ，由最高优先级的生效锚定条目独占决定（单点 = 其残差；点对/边缘 = 其两端残差均值）；低优先锚不参与 Δ，其残差如实保留并可在编辑器/导出报告里点名——不做加权均分（均分意味着每只脚都滑一点，违背「锚定不滑动」）。低优先锚仍可动用自己的局部手段：其所在节点的局部旋转（下条）。
- 点对/边缘在平移下：两端残差进所属条目的 Δ 计算——中点精确贴合、**段的倾斜原样保留**（spike C1）。脚掌底边斜着落地时，平移只能让中点贴地、边仍斜。
- 边缘/点对的倾斜由**锚点所在节点自己掰正**（2026-10-28 裁决 1）：旋转补偿只作用于锚点所在节点的局部角度，绕冻结锚点转，把边对齐到目标段方向（spike E：锚点分毫不动、边另一端精确贴地、整角色与其余节点不受影响）。整角色绝不因锚定被掰转。点对跨两个节点时，旋转由主点（第一个点）所在节点承担，另一端随 FK 与 Δ 跟随。3D 里绕段轴的滚动仍不定（点对只定 5 个自由度），靠姿态保持，不在本机制内解。

## 五、状态：每锚一条冻结记录，顺序求值确定

冻结语义必然带状态（冻结位 = 生效帧的结算位，之后帧算不出），状态量极小：每锚一条 `{冻结位}` 或未生效。规则：

- 顺序求值确定性：从「全部未生效」的起点逐帧求值，同一时间轴结果唯一（spike D2）；播放、convert 采样窗、运行时播放器都是顺序求值，天然适配。
- 求值起点 = **片段起点的状态缓存**（2026-10-28 裁决 6）：每个片段（表演/采样窗）起点持有一份锚定状态快照（各锚冻结记录或未生效），由从工程起点（或最近仍有效的缓存点）顺序求值得到并缓存。单片段预览/scrub = 取该片段起点的快照为初态、从片段内首帧演到当前帧，片段内永远一致，也不必重演全程。
- 缓存失效：任何影响结算的编辑（轨道、IK 链、锚定定义、场景）使**编辑帧之后**的片段起点快照全部失效，从最近仍有效的快照（无则工程 0 帧、未生效初态）顺序重演重建；重建惰性化（用到某片段时才补算它之前的链）。convert 整窗采样与缓存同一语义：顺序求值时在片段界读/写快照。运行时播放器是顺序播放、状态自然延续，不需要缓存（宿主 seek 回表演起点时按未生效初态起算，与编辑器片段口径一致）。
- scrub 跳帧：跳到的帧若锚本应生效中，冻结位需从求值起点重演到该帧才知道（成本 = 起点到该帧的帧数 × 单帧结算）。编辑器可接受（片段通常短）；长轴上可缓存逐帧冻结记录供 scrub 复用。
- 跨界一致性由裁决 6 的缓存解决：后片段的初态 = 前片段末状态的快照，一脚跨片段时冻结位原样带过，不重建、不跳变。
- 运行时播放器：顺序播放、状态自然延续；宿主 seek/重播时随表演起点重置，与编辑器片段口径对齐。

## 六、编辑器侧接线点（落地时）

- 数据：`Character` 加 `clampAnchors?: ClampAnchor[]`（与 `ikChains` 并列，`src/lib/unified-types.ts` 约 1312 行旁）；点引用与触发定义见 §八草案。
- 求值：`computeWorldTransforms` 加可选尾参——锚定上下文（各锚冻结记录，由调用方持有：编辑器播放会话 / convert 采样窗 / 覆盖层重演），结算后执行触发求值与刚性反移段；点解析需要结算后的 transforms 与当帧精灵（`resolveNodeSpriteId` + `markPointPx`，与 IK 尖端长解析同路）。无锚定上下文的调用（静态取位）默认不生效、不反移，行为与现状一致。
- 著者交互：画布上点选指定点直接复用编号拾取（命中给节点 + 精灵内像素位）；高度线/目标点/范围以覆盖层小部件绘制；面板按「点—触发—优先级」列表编辑。锚点生效状态应在画布上有可见标记（生效时点变色/连线到锚点位），否则用户无法判断脚为何不跟轨。
- convert：著者触发（高度/点/范围）随采样自然进包——根位移进入根节点采样曲线，与 IK 覆写进包同路；**场景触发不进采样**（见 §七），采样时须跳过 `scene` 类锚，避免与播放器双重施加。

## 七、运行时包：自动运用于所有地面和平台

现状（三处实证）：
- 包格式有场景：`ProcRuntimePackage.scene?: { solids: {x,y,w,h}[] }`（`src/lib/proc-runtime/convert.ts:212`，由工程 `projectData.scene.solids` 发出，约 1798 行）；坐标为世界单位、Y 向上、左下角 + 宽高。
- 播放器（`runtime-template.ts`）：物理体 `char` 与 `solids` 全部矩形统一碰撞（着地/贴墙/抓边沿，约 2191–2290 行），包内无场景时有内置默认关卡（约 1858–1865 行）。行为层已有 `grounded/wall/ledge` 保留变量（宿主/模板逐帧给值），说明「与环境的关系」在运行时是一等输入。
- 贴地现状只有粗粒度一招：`localGround` = 全部部件最低点 − 4px，角色原点据此对世界地面 y=0（约 795–800 行、`charOriginY` 1875 行）。它不认平台（固体顶面）、不认指定点（一刀切最低点）、俯视模式不适用。

设计：
- **包内新增锚点定义**（挂在部件上）：`{ partKey, mark?: string（点标记名）, local?: [x,y]（无标记时局部点）, mode }`；部件精灵/摞在包内本就带 `marks`（convert 约 58/139/146/168 行），命名点零新增解析——播放器用部件当帧位姿（`partCenter` 约 2295 行的同路求值）把局部点变世界点。
- **播放器逐帧锚定遍**（在表演求值后、绘制前）：对每个锚点 × 每个固体顶面：点在固体水平跨度内且点位在顶面下方吸附带内（或穿入）→ 生效并冻结（接触位投影到顶面后的整位；之后该锚每帧 Δ 只认冻结位、不再逐帧重投影——踩住就不滑）；汇总 Δ（硬优先级：最高优先锚独占），Δ 按裁决 3 **回写物理体**（下条）。顶面锚的实际 Δ = 竖直贴合分量 + 冻结 X 的横向抵消分量（点被宿主动量横推时由 Δx 抵消，即反向横移）。
- **Δ 回写物理体**（2026-10-28 裁决 3）：帧序 = 物理步 → 表演求值 → 锚定求值 → Δ 累进物理体位置（`char.x/char.y`）→ 绘制（绘制原点即回写后的物理位置，不再另设绘制替身）。锚定在运行时由此成为物理事实：下一帧的着地/贴墙/抓边判定都从回写后的位置出发；释放帧没有累计偏移要吞、不跳。录制回放不受影响——回写在模板模拟之内、是（包， 输入序列）的确定函数，回放重演即重建同一锚定状态。回写与碰撞的先后天然错开：锚定在本帧末改位置、碰撞解算在下一帧物理步开头照常推出穿入，两者不抢同一时刻。编辑器侧没有物理体，此条仅运行时适用。
- **俯视模式**（`moveMode === 'top'`）：地面/平台是平面区域——触发 = 点进入固体矩形区域（范围触发的运行时版），锚定语义为区域内钳制（点不画出区域外），Δ 同路。
- **自动的含义**：触发集 = 包内 `scene.solids` 全体，新平台进场景即自动生效，不逐个表面设置。锚点纳入走**约定**（2026-10-28 裁决 5）：部件上名为 `anchor` 的点标记自动成为运行时锚点，convert 与播放器自动处理，**UI 侧无感**——不加面板、不加开关（要排除某个点，改标记名即可）。
- 预览口径（2026-10-28 裁决 4）：场景固体的锚定效果在**程序化预览面板**里看（该面板跑的就是运行时模板 + 场景物理，与发布行为同一条路）；主画布只呈示著者触发（高度/目标点/范围），不把场景固体画进主画布触发集。

## 九、分期

- 一期（编辑器/求解侧）：`computeWorldTransforms` 锚定段 + 锚定上下文；节点/像素点（命名标记）；高度/目标点触发；刚性反移；最小面板 + 画布触发 gizmo + 生效标记；探针覆盖 spike 案例 A/B/D 的产品版。运行时 `scene` 触发不做，但数据结构预留。
- 二期：点对/像素对/精灵边缘（平移语义）、目标范围触发、场景固体在编辑器预览纳入、convert 采样接入（著者触发进包、`scene` 触发跳过）。
- 三期（运行时包）：convert 发锚点定义；播放器锚定遍对全部固体自动适用（侧视顶面 + 俯视区域）；着地回写按裁决；模板冒烟加锚定案例（脚踩平台逐帧断言）。

## 十、裁决记录

全部已裁决（2026-10-28）：
1. **旋转只掰锚点所在节点**：整角色不转；边缘/点对的对齐旋转由锚点所在节点绕冻结锚点承担（§四、spike E）。
2. **反移后重解 = 可设置的选项**：逐锚 `resettle` 开关，默认关（§三）。
3. **运行时 Δ 回写物理体**：锚定在运行时是物理事实——Δ 累进 `char.x/char.y`，着地/抓边判定从回写后位置出发，释放不跳，回放仍确定（§七）。
4. **场景在程序化预览面板看**：主画布不纳入场景固体触发，运行时贴合效果以程序化预览面板为准（§七）。
5. **运行时锚点走约定、UI 侧无感**：名为 `anchor` 的点标记自动纳入，不加面板与开关（§七）。
6. **求值起点 = 片段起点的状态缓存**：每片段起点缓存锚定状态快照，预览/scrub 从快照起算；编辑使编辑帧之后的快照失效、从最近有效缓存顺序重建（§五）。
7. **多锚硬优先级**：Δ 由最高优先锚独占决定，低优先残差如实点名，不均分（§四）。
