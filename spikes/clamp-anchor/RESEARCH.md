# 钳制锚定研究：指定点到达钳制条件后锚定、角色其余部分反向移动

需求原话：「指定点（节点/节点对/像素/像素对/精灵边缘）由 IK 结算到达所设置钳制高度/目标点/目标范围时，暂时锚定该指定点位置，将角色其他部分反向移动以满足 IK 结算结果」；追加：「运行时包自动运用于所有地面和平台」。

## 结论先行

机制可定式为一句话：**每帧先照常 IK 结算，在结算位上求值触发；触发后锚点位由纯函数给出（高度→投影到高度面、目标点→目标本身、范围→钳进区域、场景固体→投影到固体表面），锚定覆盖该点所属链的目标，根平移 Δ = 锚点位 − 结算位（多锚取加权最小二乘），带 Δ 重结算，迭代 2–3 遍至收敛。** 锚点不靠状态记忆，任意帧独立求值——scrub、convert 采样、运行时逐帧都同口径。spike（`spike.mts`，11 条断言全过）已验：单点锚精确收敛、下蹲时穿深由身体反推吸收、多锚平移补偿的最小二乘最优性与权重优先级、边缘锚在平移下的边界（中点贴合、倾斜保留）与带旋转时的精确解、锚点位幂等性。

运行时包侧：包格式已有场景固体（`scene.solids`，AABB 列表），播放器物理已对全部固体统一碰撞；缺的是按指定点的贴合——现只有整角色一刀切的 `localGround`（所有部件最低点 −4px 对世界地面 y=0）。设计：convert 把锚点定义随包发出（部件 + 命名标记/局部点），播放器逐帧求值表演后，把每个指定点对**全部**固体的顶面（地面/平台）做同一套触发/锚定/反移，对绘制原点施加 Δ——不逐个表面著者设置，即「自动运用于所有地面和平台」。此事不能烘焙进 convert 采样：角色位置由宿主运行时驱动，同一表演在任意位置播放，贴合必须在播放器按当帧位置求值。

## 一、指定点：五种来源，统一解析为世界点（对）

锚定的对象在求值时一律落成 1 个或 2 个世界点（点对/边缘 = 有序点对）：

| 来源 | 解析口径 |
|---|---|
| 节点 | 关节世界位（结算后 WorldTransform 的 worldX/Y/Z） |
| 节点对 | 两关节世界位，成段 |
| 像素 | 节点当前精灵上的像素：优先命名标记（`SpriteMark` 的 point 类，`markPointPx` 解析为精灵像素位），或裸坐标；精灵局部 → 节点局部（减 plug）→ 世界 = 节点位 + `applyFrameRotation(帧, 局部偏移, 朝向)`，与子关节偏移同一公式 |
| 像素对 | 两像素同上，成段 |
| 精灵边缘 | 精灵矩形四边之一（plug 相对的两角点）解析为世界段；或由两点标记定义边 |

堆叠件上的像素：摞的合成图有自己的局部空间（摞原点 + 层序），像素点可按合成图坐标解析，世界位走摞的当帧帧——与精灵像素同构，建议二期再开，一期只认普通精灵与节点。

## 二、触发：三种著者触发 + 一种场景自动触发

触发一律在**平结算位**（未施加任何锚定补偿的当帧位姿）上求值——释放判定因此不依赖补偿后位置，不会自锁：

- **钳制高度**：点的世界 Y 越过高度面（编辑器 Y 向下：地面 = Y ≥ 线；天花板反之）。锚点位 = 点投影到该面（Y 置线、X/Z 用结算值）。
- **目标点**：点与目标点距离 ≤ 半径（到达）。锚点位 = 目标点本身。
- **目标范围**：点进入区域（矩形/圆形，可带 Z 区间）。锚点位 = 结算位钳进区域（已在内则原位冻结为锚——注意：区域内冻结需要「进入那一刻的位置」，纯函数近似 = 当前结算位；只要点还在区域内，每帧锚点位 = 当帧结算位、Δ 恒为投影差，行为等价于把点约束在区域内滑动，见下「范围内滑动」注）。
- **场景固体（运行时自动）**：点在某固体顶面的水平跨度内、且点位低于顶面 + 吸附带（或穿入）：触发。锚点位 = 点投影到顶面。全部固体逐个试，取穿深最小/最近者。编辑器侧若工程带场景固体，预览应同口径纳入（待裁决 5）。

注：「范围内滑动」与「钉死」的区别：高度/固体面锚定是把点钉在面上但允许沿面滑动（X 取当帧结算值）——这正是走路贴地想要的；目标点锚定是真钉死（XYZ 全冻结）；范围锚定默认面内滑动、区域即滑动域。若要「进入范围即钉死在进入点」，那是带状态的语义（要记进入帧位置），与无状态定式冲突，一期不做（待裁决时可议）。

## 三、反向移动：根平移补偿 + 覆盖同点目标 + 迭代

- 补偿通道唯一的落点是**根节点世界位**：`computeWorldTransforms` 现在是「FK → 解链覆写 → 带覆写重算」的两遍结构（`src/lib/unified-render.ts` 约 486 行起、IK 段约 576–596 行，`solveChainIKOverrides` 约 691 行）。锚定加第三段：结算后求值锚点 → 算 Δ → 以 `worldOffset` 入参重跑（根世界位 += Δ）并重解各链。Δ 必须进 `computeWorldTransforms` 内部、不能在渲染计划层平移了事——拾取、覆盖层、convert 采样都只认这一个取位出处，进内部才全线同源（与 IK 覆写同理）。
- **锚定覆盖同点目标**：生效期间，该点若是某链的末端/尖端，该链目标换成锚点位再解（spike 案例 A 的收敛前提）。否则链会把点拉回原目标、与锚定对冲，迭代不收敛。不覆盖的话语义是「两约束拔河」，不建议（待裁决 2）。
- 其余链目标是世界量、根平移后照常重解——下蹲时脚钉地、髋轨下沉，腿链以锚点位为目标重弯，身体其余链（如手撑目标）保持世界位，这就是「其余部分反向移动以满足 IK 结算结果」的全貌：被反移的是根（整角色），被满足的是各链原本的世界目标。
- 迭代上限建议 3 遍，残差 < 0.05px 停；不收敛（约束互斥）时保留最后一遍结果并把最大残差记进导出报告/编辑器提示，不静默。

## 四、多锚、点对与边缘：平移自由度的边界

- 多点同帧生效：单遍 Δ 取各锚残差的**加权平均**（平移最小二乘最优解，spike B1）；权重即优先级（B2：权重 3 的锚补偿后残差显著更小）。硬优先级（先满足高优先、再在其零空间内满足低优先）数学上更强但实现复杂，一期权重制足够，待真机手感再议。
- 点对/边缘在平移下：两端残差进同一次加权平均——中点精确贴合、**段的倾斜原样保留**（spike C1）。脚掌底边斜着落地时，平移只能让中点贴地、边仍斜。
- 要两端同时精确（边贴合面、点对锁距锁向），自由度必须加**绕角色根的面内旋转**（spike C2：平移+旋转两端误差 0.00）。3D 里点对还剩绕对轴的滚动自由——点对锚定天然定不了滚动，需要第三点或姿态保持项。是否一期就带旋转是待裁决 1：带旋转会让整角色在锚定时可被掰转，观感与风险都更大；建议一期平移、点对/边缘按中点+平均残差语义明示，二期加旋转档。

## 五、状态性：无状态定式（本研究的关键取舍）

锚点位三式（投影/目标/钳入）都是结算位的纯函数且幂等（spike D1/D2）。于是：

- 不需要「上一帧是否生效」的记忆 → 时间轴 scrub 跳帧、convert 逐帧采样（采样窗内逐帧独立）、运行时任意帧率，都不会因状态缺失而错位。
- 迟滞（防触发边界抖动）不靠状态实现：高度触发用吸附带几何吸收（带内锚定、带外释放，天然有进出差）；目标点触发的半径本身即迟滞域。
- 代价：§二注的「进入点钉死」做不了；步态里脚跟→脚掌的滚动锚切换（先锚跟、后锚掌）只能靠两个锚的触发条件先后成立近似，做不到严格时序状态机。若日后要真状态，状态必须按（角色， 锚）存进播放/采样上下文并明确 scrub 回退语义——另行立项再议。

## 六、编辑器侧接线点（落地时）

- 数据：`Character` 加 `clampAnchors?: ClampAnchor[]`（与 `ikChains` 并列，`src/lib/unified-types.ts` 约 1312 行旁）；点引用与触发定义见 §八草案。
- 求值：`computeWorldTransforms` 加可选尾参 `worldOffset` 与锚定遍；触发求值需要结算后的 transforms 与点解析（像素点要当帧精灵解析——`resolveNodeSpriteId` + `markPointPx`，与 IK 尖端长解析同路）。
- 著者交互：画布上点选指定点直接复用编号拾取（命中给节点 + 精灵内像素位）；高度线/目标点/范围以覆盖层小部件绘制；面板按「点—触发—优先级」列表编辑。锚点生效状态应在画布上有可见标记（生效时点变色/连线到锚点位），否则用户无法判断脚为何不跟轨。
- convert：著者触发（高度/点/范围）随采样自然进包——根位移进入根节点采样曲线，与 IK 覆写进包同路；**场景触发不进采样**（见 §七），采样时须跳过 `scene` 类锚，避免与播放器双重施加。

## 七、运行时包：自动运用于所有地面和平台
