# 机甲部位共性 × 程序化叠加生成调研（research/mecha-part-patterns）

基点：main 22e8b6d（PR #87 合并后）。题目（用户原话）：研究机甲图片中
特定部位（比如腿部）的共性（即模式），是否可以用多次程序化生成的
方式叠加出同样特点的图（蓝图像素链或模式库/模式组合）。

样本来源：内置参考图库的机甲侧视图（用户指定：用图库机甲，或生成
更多参考图；本轮图库样本已够，未额外生成）。图库机甲共 15 张，腿部
细看样本取 6 张：主战步行坦克、侦察步行机、重型机甲（原有参考）、
六足重炮步行车、巨型陆地战舰、巨型钻击机甲。

## 一、腿部共性提炼

六张样本逐项对读，腿的「模式」分四层，每层都是可参数化的规则：

### 1. 结构语法（骨架）
- 主流是两段链：髋—膝—踝三关节，段长比约大腿 1 : 小腿 0.95，
  宽度从髋到踝递减（锥形）。
- 变体只有拓扑开关：膝前屈（标准）/ 膝后屈（侦察机反关节）/ 直柱
  （陆地战舰的承重柱腿）。构件种类不变。
- 多腿机器是**同一个腿单元的重复**：陆地战舰九条腿逐条同形、六足
  重炮同一单元换姿态角。重复 + 相位差是结构层的一等模式。
- 脚恒为低矮宽掌 + 前趾块，踝盘压在掌上。

### 2. 构件语法（中层）
- **分板**：每段装甲不是一整块，而是沿段长切 2–3 板，板缝露深色
  内框。六张样本无一例外。
- **前护板**：小腿前方常另叠一块大板（主战坦克、重型机甲最明显），
  是独立一层，不与段板共面。
- **关节盘**：关节处一律同心圆盘（外环 + 内盘 + 毂心螺栓），半径
  约段宽的 0.9 倍；踝盘略小。
- **活塞**：每关节配一根液压活塞跨关节连接两段，深色缸筒 + 高亮
  活塞杆；位置有规律——大腿根多在后侧、小腿根多在前侧。
- 段内框（骨架杆）在板缝与关节间隙处露出，颜色近黑。

### 3. 表面语法（场层）
逐像素看是几个场的叠加，与结构无关、只跟局部坐标有关：
- 柱面明暗：段横截面中间亮、两侧暗（圆柱感）。
- 纵向渐变：板上部略亮、下部略暗；板与板之间有一步色差。
- 棱线：每块板上缘 1px 提亮、下缘 1px 压暗，板的立体感主要来自
  这一对线而不是大渐变。
- 细节词表（位置被结构锚定、样式固定）：警示斜纹/箭头（涂在前护
  板或小腿板）、通风栅（大腿板上部横排短缝）、面板线（板内一条
  横向暗线）、螺栓排（沿板缘等距点）、贴纸小字（CAUTION/编号）、
  信号灯小亮点。
- 描边：整剪影 1px 近黑边。

### 4. 配色语法
主装甲 1–2 色（同色系明暗两档）+ 内框近黑 + 金属灰（盘/缸筒）+
铬亮（活塞杆）+ 单一强调色（橙，六张里五张是橙）。配色是整腿一张
小色板，与结构完全解耦。

## 二、叠加管线（spike 实现）

`gen-legs.mts` 独立实现八层，每层一次程序化生成，层间靠三张参数图
（owner=分件号、u=件内横坐标、v=件内纵坐标）黏合：

1. 布局：关节链（髋/膝/踝/趾坐标 + 拓扑开关 + 弯曲量）→ 各段宽度。
2. 剪影：段四边形 ∪ 关节盘 ∪ 脚掌趾块。
3. 分板：沿段长切板、留缝；缝里不填 → 天然露内框色。
4. 构件：关节盘（同心圆三档）、活塞（筒 + 杆两段线宽形状）、前护板
   另叠一层。
5. 基色：按色板填，板间用种子给 ±8% 色差（单元哈希的用法）。
6. 场着色：柱面场（|u| 衰减）× 纵向渐变，盘按半径分档，杆给高光。
7. 细节：条纹（锚定前护板、按 v 带 + 斜纹条件）、通风栅、面板线、
   螺栓点（哈希采样 + 近缝条件）。
8. 棱线与描边：owner 变化处上亮下暗；剪影外缘描近黑。

输出（out/）：4 个变体（橄榄标准 / 沙漠标准 / 灰蓝反关节 / 锈色
标准，只换拓扑、色板、种子、弯曲量）、双腿站姿（同单元两种弯曲
量并置）、与主战步行坦克参考腿的对照图。

## 三、实验结论（逐项对共性清单）

| 共性 | 叠加复现 | 备注 |
|---|---|---|
| 两段链 + 三盘 + 锥形 | ✓ | 布局层参数 |
| 反关节变体 | ✓ | 只换膝坐标符号 |
| 同单元重复（双腿/多腿） | ✓ | pair-olive.png；相位差即弯曲量参数 |
| 分板留缝见内框 | ✓ | 分板层 |
| 前护板 | ✓ | 独立叠层 |
| 活塞（筒+亮杆、跨关节） | ✓ | 位置规律按样本写死为缺省 |
| 柱面/纵向场、板间色差 | ✓ | 场着色层 |
| 棱线对（上亮下暗） | ✓ | 效果比预期强，是板感主来源 |
| 警示条纹 | ✓ | 锚定前护板 |
| 通风栅 / 面板线 | △ | 层在、低分辨率下可见度弱 |
| 螺栓排 | △ | 采样条件成立但点太小，几乎看不见 |
| 贴纸小字 | ✗ | 未做；属细节词表扩充，非范式问题 |
| 做旧斑驳（锈渍/划痕） | ✗ | 未做；值噪声阈值场可补（现有算子有噪声场） |
| 板形斜切/多层交错 | △ | spike 板形只有直切四边形；参考图板有斜切与交错搭接，属布局层形状原语扩充 |
| 姿态（行走中弯曲姿态） | △ | 弯曲量参数已留；全身姿态是骨骼/IK 的事，不在本题 |

分辨率口径：spike 画布 200×280，参考图 1920×1280。本轮只比语法
是否齐备、是否可参数化，不比像素密度；细节层可见度随分辨率上升
会自然改善（条纹/栅格都是按局部坐标的场，不依赖分辨率）。

**总判定：部位共性可以由多次程序化生成叠加复现。** 共性清单里
结构层与构件层全部、表面层大部，都能写成参数化的一层且层间只靠
参数图耦合；换拓扑/色板/种子即得同族新图，这正是「模式」的定义。
达不到的是参考图的细节密度与不规则感，缺的是词表与形状原语的量，
不是叠加范式本身。

## 四、与现有机器对位

用户问的两个候选载体，代码实查结论：

- **表面层 → 现有表面模式（SurfaceGraph + surface-ops）重合度
  最高。** `src/lib/proc-runtime/surface-ops.ts` 49 个算子规格里，
  场源已有条纹、棋盘、柱面渐变、线性渐变、值噪声、团块、Voronoi、
  边界邻近（edgeProx）、归一深度、横纵坐标等——spike 第 6/7 层用
  的场大半已存在。缺的是**输入图**：现有场源的 inside/dist/h 都
  基于一整张已有精灵的剪影，没有「分件号」与「件内局部坐标」两
  种场源。补 `partId` / `partU` / `partV` 三个场源，表面机器就能
  直接消费结构层输出。
- **结构层与构件层 → 两套现有机器都缺位。** 蓝图像素链现有像素
  算子是整图变换（描边/翻转/镜像/抖动/换色/位移/柱面旋转/球面
  旋转/逐点编辑），没有「从关节链规格生成剪影 + 分件图」的源
  节点；模式库的动态图案是逐帧效果层（形变/追随/发射/辉光），
  与静态部件生成正交，不承担此事。
- 因此真正的缺口只有一个：**结构生成前端**——关节链规格 →
  剪影 + 分件 owner 图 + 局部坐标图。它的输出恰好是表面场图的
  理想输入；后段复用现成机器，不需要再造轮子。

## 五、落地路线（若立项，供裁决）

- **甲（推荐先行）：装配向导加「程序生成部件」入口。** 结构生成器
  产出分件图（每板一部件、自带关节点位），直接进现有拆分/对位/
  装配流程，用户在生成结果上修——生成物是草稿与起点，不冒充
  成品。风险小、复用整条装配线。
- **乙：结构生成做成蓝图像素链的源节点 + 表面模式补三个场源。**
  生成结果成为可接线、可参数驱动、可进包的活管线，想象空间大，
  但动蓝图 IR 与表面求值两处，量级明显大于甲。
- 两条路线共用同一个结构生成器内核（本 spike 的布局+分板+构件
  三层），先甲后乙不浪费。
