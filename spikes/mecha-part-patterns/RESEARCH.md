# 机甲部位共性 × 程序化叠加生成调研（research/mecha-part-patterns）

基点：main 22e8b6d（PR #87 合并后）。题目（用户原话）：研究机甲图片中
特定部位（比如腿部）的共性（即模式），是否可以用多次程序化生成的
方式叠加出同样特点的图（蓝图像素链或模式库/模式组合）。

样本来源：内置参考图库的机甲侧视图（用户指定：用图库机甲，或生成
更多参考图；本轮图库样本已够，未额外生成）。图库机甲共 15 张，腿部
细看样本取 6 张：主战步行坦克、侦察步行机、重型机甲（原有参考）、
六足重炮步行车、巨型陆地战舰、巨型钻击机甲。

## 一、腿部共性提炼

六张样本逐项对读，腿的「模式」分四层，每层都是可参数化的规则：

### 1. 结构语法（骨架）
- 主流是两段链：髋—膝—踝三关节，段长比约大腿 1 : 小腿 0.95，
  宽度从髋到踝递减（锥形）。
- 变体只有拓扑开关：膝前屈（标准）/ 膝后屈（侦察机反关节）/ 直柱
  （陆地战舰的承重柱腿）。构件种类不变。
- 多腿机器是**同一个腿单元的重复**：陆地战舰九条腿逐条同形、六足
  重炮同一单元换姿态角。重复 + 相位差是结构层的一等模式。
- 脚恒为低矮宽掌 + 前趾块，踝盘压在掌上。

### 2. 构件语法（中层）
- **分板**：每段装甲不是一整块，而是沿段长切 2–3 板，板缝露深色
  内框。六张样本无一例外。
- **前护板**：小腿前方常另叠一块大板（主战坦克、重型机甲最明显），
  是独立一层，不与段板共面。
- **关节盘**：关节处一律同心圆盘（外环 + 内盘 + 毂心螺栓），半径
  约段宽的 0.9 倍；踝盘略小。
- **活塞**：每关节配一根液压活塞跨关节连接两段，深色缸筒 + 高亮
  活塞杆；位置有规律——大腿根多在后侧、小腿根多在前侧。
- 段内框（骨架杆）在板缝与关节间隙处露出，颜色近黑。

### 3. 表面语法（场层）
逐像素看是几个场的叠加，与结构无关、只跟局部坐标有关：
- 柱面明暗：段横截面中间亮、两侧暗（圆柱感）。
- 纵向渐变：板上部略亮、下部略暗；板与板之间有一步色差。
- 棱线：每块板上缘 1px 提亮、下缘 1px 压暗，板的立体感主要来自
  这一对线而不是大渐变。
- 细节词表（位置被结构锚定、样式固定）：警示斜纹/箭头（涂在前护
  板或小腿板）、通风栅（大腿板上部横排短缝）、面板线（板内一条
  横向暗线）、螺栓排（沿板缘等距点）、贴纸小字（CAUTION/编号）、
  信号灯小亮点。
- 描边：整剪影 1px 近黑边。

### 4. 配色语法
主装甲 1–2 色（同色系明暗两档）+ 内框近黑 + 金属灰（盘/缸筒）+
铬亮（活塞杆）+ 单一强调色（橙，六张里五张是橙）。配色是整腿一张
小色板，与结构完全解耦。

## 二、叠加管线（spike 实现）

`gen-legs.mts` 独立实现八层，每层一次程序化生成，层间靠三张参数图
（owner=分件号、u=件内横坐标、v=件内纵坐标）黏合：

1. 布局：关节链（髋/膝/踝/趾坐标 + 拓扑开关 + 弯曲量）→ 各段宽度。
2. 剪影：段四边形 ∪ 关节盘 ∪ 脚掌趾块。
3. 分板：沿段长切板、留缝；缝里不填 → 天然露内框色。
4. 构件：关节盘（同心圆三档）、活塞（筒 + 杆两段线宽形状）、前护板
   另叠一层。
5. 基色：按色板填，板间用种子给 ±8% 色差（单元哈希的用法）。
6. 场着色：柱面场（|u| 衰减）× 纵向渐变，盘按半径分档，杆给高光。
7. 细节：条纹（锚定前护板、按 v 带 + 斜纹条件）、通风栅、面板线、
   螺栓点（哈希采样 + 近缝条件）。
8. 棱线与描边：owner 变化处上亮下暗；剪影外缘描近黑。

输出（out/）：4 个变体（橄榄标准 / 沙漠标准 / 灰蓝反关节 / 锈色
标准，只换拓扑、色板、种子、弯曲量）、双腿站姿（同单元两种弯曲
量并置）、与主战步行坦克参考腿的对照图。

## 三、实验结论（逐项对共性清单）

| 共性 | 叠加复现 | 备注 |
|---|---|---|
| 两段链 + 三盘 + 锥形 | ✓ | 布局层参数 |
| 反关节变体 | ✓ | 只换膝坐标符号 |
| 同单元重复（双腿/多腿） | ✓ | pair-olive.png；相位差即弯曲量参数 |
| 分板留缝见内框 | ✓ | 分板层 |
| 前护板 | ✓ | 独立叠层 |
| 活塞（筒+亮杆、跨关节） | ✓ | 位置规律按样本写死为缺省 |
| 柱面/纵向场、板间色差 | ✓ | 场着色层 |
| 棱线对（上亮下暗） | ✓ | 效果比预期强，是板感主来源 |
| 警示条纹 | ✓ | 锚定前护板 |
| 通风栅 / 面板线 | △ | 层在、低分辨率下可见度弱 |
| 螺栓排 | △ | 采样条件成立但点太小，几乎看不见 |
| 贴纸小字 | ✗ | 未做；属细节词表扩充，非范式问题 |
| 做旧斑驳（锈渍/划痕） | ✗ | 未做；值噪声阈值场可补（现有算子有噪声场） |
| 板形斜切/多层交错 | △ | spike 板形只有直切四边形；参考图板有斜切与交错搭接，属布局层形状原语扩充 |
| 姿态（行走中弯曲姿态） | △ | 弯曲量参数已留；全身姿态是骨骼/IK 的事，不在本题 |

分辨率口径：spike 画布 200×280，参考图 1920×1280。本轮只比语法
是否齐备、是否可参数化，不比像素密度；细节层可见度随分辨率上升
会自然改善（条纹/栅格都是按局部坐标的场，不依赖分辨率）。

**总判定：部位共性可以由多次程序化生成叠加复现。** 共性清单里
结构层与构件层全部、表面层大部，都能写成参数化的一层且层间只靠
参数图耦合；换拓扑/色板/种子即得同族新图，这正是「模式」的定义。
达不到的是参考图的细节密度与不规则感，缺的是词表与形状原语的量，
不是叠加范式本身。

## 三之二、复现加强轮（v2，用户指出复现程度不够后追加）

v1 的差距逐条立账，v2（`gen-legs-v2.mts`，画布 380×540，管线扩
到十二层）逐条销账：

| v1 差距 | v2 对策 | 结果 |
|---|---|---|
| 姿态直挺 | 站姿关节角：膝前屈 50px、小腿后收、踝补偿，脚掌平贴地 | ✓ 折线姿态成立 |
| 渐变顺滑不像像素画 | 全程色阶量化：每色 6 档坡道、暗部偏冷 | ✓ 坡道感成立 |
| 板形只有直切 | 板端斜切（plateTest 两端削角）、上下板搭接（下板盖上板边、无缝改台阶影）、多边形护板/膝盖帽/脚趾 | ✓ |
| 没内框垫底 | 布局先画内框杆（沿轴窄带），板缝与板侧自然露出 | ✓ |
| 没线缆 | 两段贝塞尔线缆（髋后→膝后→踝后）垫在板下 | △ 只在板缝/后侧露出，符合参考（参考线缆也多半隐半现） |
| 贴纸小字 ✗ | 3×5 点阵字：护板 CAUTION + 警告三角、大腿编号 M-××（种子生成） | ✓ 放大核验字形正确 |
| 通风栅/螺栓 △ | 栅格成块（大腿下板）、铆钉沿板缘等距 2px 点 + 高光 | ✓ 放大可见 |
| 没做旧 ✗ | 三层：噪声啃边（边缘咬成内框色）、种子划痕（只落板面）、底部积尘（越下越暗+斑驳）；橄榄/沙漠另加迷彩斑（低频噪声阈值混色） | ✓ |
| 关节盘太素 | 金属环带按角度分 8 扇区交替压暗（刻槽）、毂心分档 | ✓ |
| 构件密度低 | 膝盖帽（多边形）、大腿前小盒、小腿后挂盒 | △ 有改善，仍少于参考 |

v2 对照（out/v2-compare-mbt.png）后仍剩的差距，如实记：
- **轮廓气势**：参考腿更粗壮、折线更狠，护板是主导盾形；v2 护板
  仍是贴面带状。差在布局层的比例与护板形状原语（护板可放大到
  覆盖小腿正面 70% 并下探尖头），属参数与原语量。
- **暗部深度**：参考在关节窝、板搭接处有近黑的深影；v2 压暗幅度
  保守。可加一层「凹陷暗影」：owner 边界内侧第二圈再压一档 +
  关节盘周围一圈暗晕。
- **中型构件**：参考有膝连杆、提手、副油缸等中型件；v2 只有膝盖
  帽与两个小盒。属构件词表继续扩充（每加一类原语，密度上一个
  台阶——v1→v2 已验证这条规律两次）。

加强轮的意义：差距收窄的每一步都来自「多加一层 / 多一类原语」，
没有一步需要换范式。这把第三节的结论从「词表量问题」变成了
实测规律：**复现程度 ≈ 层数 × 词表量，可按预算逐项买**。

## 三之三、区别模式提取与迭代收敛（v3 → v5，用户令：用更多参考图提取区别模式、多迭代至消失）

方法换挡：不再只对一张参考图眼比。样本扩到图库全部机甲 17 张
（腿部裁图 16 张可用，mecha-side 一张裁图失败剔除），区别模式用
两路证据提取：

- **量化指标**：剪影内暗部占比（亮度<55）、深暗部（<32）、亮部
  （>175）、内边缘密度（相邻像素亮度差>42 的比例，代理细节密度）、
  强调色占比、亮度标准差（对比度）。背景按参考图纯色底识别、
  生成图按透明通道识别，口径一致。
- **特征在场矩阵**：25 项特征逐样本在场打分，取「参考高频而生成
  缺席」者为区别模式。

### 基线（v3 对参考）

| 指标 | 参考·载具族（14 样本） | 参考·人形族（2 样本） | 生成 v3 |
|---|---|---|---|
| 暗部 | 0.56 | 0.29 | 0.24 |
| 深暗部 | 0.34 | 0.23 | 0.14 |
| 亮部 | 0.02 | 0.31 | 0.03 |
| 内边缘密度 | 0.086 | 0.183 | 0.102 |
| 强调色 | 0.035 | —（橙/蓝各一） | 0.035 |
| 对比度 std | 44 | 82 | 40 |

最大区别模式是**明度整体偏高一倍**：参考腿大面积坐在深暗区
（内框、窝影、远侧腿都计入），v3 的板面太亮太干净。边缘密度与
色阶数基线已对齐——缺的不是细节数量，是明度分布与结构项。

特征矩阵提炼出的区别模式（按参考频率）：远侧腿（多腿样本 8/8、
生成无）、分趾脚（11/16、生成只有趾块 2 块）、轻型内框变体
（4/16 侦察/轨道炮/四足/兽型为内框主导、生成只有重甲一种覆盖率）、
人形壳子族（2/16 白甲光滑壳 + 色块涂装、生成无）、竖向面板线
（8/16、生成只有横线）、盘面螺栓圈（7/16、生成只有自创刻槽）、
标志图形（6/16、生成只有文字与编号）、锈色斑（4/16、生成无色相
斑）、亮掉漆（5/16、生成啃边只有暗色）、成对活塞（6/16、生成
仅大腿一对）、强调色线缆（2/16）、排气簇（2/16）。

### 迭代记录

- **v4**（gen-legs-v4.mts）：配色与板面整体压暗、缝加宽加深、
  三趾脚、竖向面板缝、盘面 8 颗环螺栓、种子标志图形（菱/十字/
  三角/横杠）、磨损斑层（锈色混色）、亮掉漆点、frameHeavy 轻型
  变体、formation 远侧腿合成。复测：暗部 0.24→0.49，但压暗过头
  压扁了对比——std 40→36、深暗部只到 0.22、边缘密度跌到 0.072、
  强调色被压到 0.020。教训：整体平移明度会同时杀掉对比度。
- **v5**（gen-legs-v5.mts）：基色后加全局调色拉伸（暗更暗、亮
  更亮，细节盖章在拉伸之后保持 crisp）、箭头纹加粗、大腿饰带、
  shellMode 人形壳变体（近无缝板 + 色块板 + 鞋式单趾 + 光滑柱面
  + 白甲配色）。

如实保留的残差（当前提取方法测不到或小众）：
- 小腿活塞未成对（大腿已成对）；人形壳变体的轮廓比例仍借载具
  骨架（语法与指标入族，体型未换）；强调色线缆仅 2/16 小众未做。
- 指标口径边界：参考裁图含少量舰体底部与远侧腿，本就计入其

- 方法测不到的手绘不规则感（板形手工斜切的随机度、贴纸的磨损
  字迹、每台机器独有的小改装）不在「区别模式」定义内——那是
  个体差异，不是共性模式。

视觉对照同步纠正：此前各轮头条对照图一直沿用 v1 选定的主战坦克
一张（对照脚本逐轮复制），与「多样本提取」口径不一致。已补多参考
对照：`out/v5-compare-multi.png` 五组按族对读（重型双足↔mecha-heavy、
反关节轻型↔walker-scout、内框主导↔walker-railgun、人形壳↔mecha-agile、
锈蚀重型↔boss-piledriver），`out/v5-compare-formation.png` 多腿阵列
↔walker-aa（近侧腿 + 远侧腿分层同框）。六组取景逐组目检过。

结论升级：区别模式是可枚举、可测量、可逐项销账的；三轮迭代
（v3→v5）把可测差距全部关进 ±0.025 与在场矩阵清零。这同时
给出了落地时的质量门做法：生成器上线后，用同一套指标 + 矩阵
对新部位（臂、躯干）重复提取即可。

## 三之四、立体感专项（v6 → v8，用户判「立体感完全没有复现」后追加）

判词成立，且是构造问题不是参数问题。通读 v5 着色链，五处构造
决定了它只能出贴纸：

1. 板面用**对称中心渐变** `(1-|u|)^1.35`——没有光向，读作软包
   而非有面的固体；参考是按面给平坦色阶（受光面/前面/转折面/
   背侧面），面的边界就是体积的边界。
2. 棱线只有 **1px** 且只处理上下方向的 owner 边界；参考的斜面
   是 2–4px 的带。
3. **没有投影**：靠前部件不在身后部件上落影，搭接处只有 v3 的
   1–2px 凹陷压暗，部件之间没有深度次序的明度证据。
4. 圆盘是同心平环，方向性明暗幅度只有 ±10%；活塞/拉杆同为
   对称渐变，两缘不收暗，读作色带不读作圆管。
5. 段的剪影是**直线收分的平行边**——轮廓本身没有隆起，内部
   着色再强也救不回来（v7 复看后确认，列为第三轮）。

先说一个测错的代理：本轮试过「5×5 局部亮度范围」当立体感指标，
测出来生成图反而高于参考——它量的是表面忙碌度（噪声、量化台阶、
面板线都计入），参考的大块平坦面反而得分低。此指标作废，
立体感的验收回到六组按族对照的目检 + 构造逐项对账，不拿代理
数字冒充。

三轮改造：

- **v6**（gen-legs-v6.mts）：板面换非对称形态剖面（前缘高光带
  1.14 / 前面 1.0 / 转折 0.85 / 背侧 0.67 / 后缘 0.53，坡道量化
  成平坦色带，护板 u 约定相反已取反）；投影层（owner 序号定
  前后，向后下偏移 −5/+6 与 −10/+12 两档 0.72/0.87）；斜面带
  （上亮唇 1.24、下暗唇 0.6 两行、纵向前亮后暗）；圆盘方向

## 四、与现有机器对位

用户问的两个候选载体，代码实查结论：

- **表面层 → 现有表面模式（SurfaceGraph + surface-ops）重合度
  最高。** `src/lib/proc-runtime/surface-ops.ts` 49 个算子规格里，
  场源已有条纹、棋盘、柱面渐变、线性渐变、值噪声、团块、Voronoi、
  边界邻近（edgeProx）、归一深度、横纵坐标等——spike 第 6/7 层用
  的场大半已存在。缺的是**输入图**：现有场源的 inside/dist/h 都
  基于一整张已有精灵的剪影，没有「分件号」与「件内局部坐标」两
  种场源。补 `partId` / `partU` / `partV` 三个场源，表面机器就能
  直接消费结构层输出。
- **结构层与构件层 → 两套现有机器都缺位。** 蓝图像素链现有像素
  算子是整图变换（描边/翻转/镜像/抖动/换色/位移/柱面旋转/球面
  旋转/逐点编辑），没有「从关节链规格生成剪影 + 分件图」的源
  节点；模式库的动态图案是逐帧效果层（形变/追随/发射/辉光），
  与静态部件生成正交，不承担此事。
- 因此真正的缺口只有一个：**结构生成前端**——关节链规格 →
  剪影 + 分件 owner 图 + 局部坐标图。它的输出恰好是表面场图的
  理想输入；后段复用现成机器，不需要再造轮子。

## 五、落地路线（若立项，供裁决）

- **甲（推荐先行）：装配向导加「程序生成部件」入口。** 结构生成器
  产出分件图（每板一部件、自带关节点位），直接进现有拆分/对位/
  装配流程，用户在生成结果上修——生成物是草稿与起点，不冒充
  成品。风险小、复用整条装配线。
- **乙：结构生成做成蓝图像素链的源节点 + 表面模式补三个场源。**
  生成结果成为可接线、可参数驱动、可进包的活管线，想象空间大，
  但动蓝图 IR 与表面求值两处，量级明显大于甲。
- 两条路线共用同一个结构生成器内核（本 spike 的布局+分板+构件

### 三之四十五、手写布局的定性（2026-11-06，用户问「为什么会有手写的布局代码」）

保留——它是渲染解释器要用的原语。先做 armIR，其余部位依次跟进，最后整机
合成为一份 IR 一次渲染。
