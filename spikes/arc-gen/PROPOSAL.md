## 一、问题定义

Pixel Composer 的一类招牌效果是**几何生成**：闪电弧（两点间
的中点置换分形折线 + 分叉）、藤蔓（沿生长方向的弯曲链 + 叶）、
星座连线（点集连线 + 节点光点）、电弧/光束。它们的共同点：

- 产物是一条（组）**折线几何**，不是部件纹理、不是粒子；
- 线有宽度衰减、颜色/辉光、随时间的抖动或生长进度；
- 锚点是语义点（部件插头、另一部件、固定偏移），不是像素。

现有模式库四段（形变/发射/粒子/发光）都表达不了它：粒子能近似
光点，表达不了连续线体。这就是它单独立项的原因。

## 二、既有基建盘点（2026-10-25 代码实查）

| 基建 | 位置 | 可复用点 |
|---|---|---|
| 刀光生成器 | `src/lib/slash-fan.ts` + 运行时孪生 | 参数化几何 → 逐帧 RGBA 光栅 → 图集瓦片 → 特效通道直读的完整先例；弧形几何（椭圆扇）已在此路上跑通 |
| 路径作者工具 | PathEditor + 蓝图 `path_follow`/`path_move` 节点 | 作者给定的折线/曲线数据结构与编辑器已有；但那是「沿路径动」，不是「生成路径」 |
| 运行时线面绘制 | runtime-template 第二绘制程序（aPos/aLocal/aColor/aMode，三角形） | 粒子 quad 走此路；厚折线可拆成逐段 quad 条带，不需要新着色器 |
| 编辑器绘制 | unified-render 的 Canvas2D | `ctx.stroke` 折线现成；动态模式粒子就是这样在节点本地层画的 |
| 双挂载/条目体系 | dynamic-patterns + library-entries | 弧线若做成动态段，可直接复用实例、效果位合并、钉版本展开 |

缺口侧：没有「折线生成函数」（中点置换/生长链/点集连线），没有
运行时折线 quad 条带构建，没有双锚点（跨部件）取位姿的消费端
接线（位姿本身两端都有：编辑器 followPoseAt 机器、运行时
elByKey + partCenter）。

## 三、路线对比

**甲：动态模式新增「弧线段」（推荐）**
- 落点：DynamicPatternParams 加弧线段（生成器类型/方向/长度/
  抖动/宽度/颜色/生长进度…），双挂载与条目体系照旧。
- 生成：纯函数 `arcPointsAt(params, t, seed)` 两端孪生（编辑器
  TS + DYNAMIC_SRC），与粒子模拟同一纪律（种子确定性、帧量化）。
- 绘制：编辑器在节点本地层 stroke；运行时把折线拆 quad 条带
  走既有第二绘制程序。
- 锚点：一期单锚点（本部件插头 + 方向/长度）；双锚点（连到另
  一部件）二期，位姿来源两端现成。
- 代价：新段 + 两端绘制各一份 + 探针孪生对拍。中等。
- 收益：直接长在模式库里，条目/父模式/覆盖全套机制即刻可用。

**乙：表演级元素（仿刀光）**
- 弧线作为表演/片段的元素（像 slash 那样定格锚点、按表演
  本地时间生成帧图）。
- 收益：一次性电弧（劈中、施法）这类「事件型」弧线最贴。
- 代价：常驻型弧线（藤蔓缠绕、星座）表达不了；且要再走一遍
  图集帧图管线。与甲不互斥——但先做乙会把常驻型缺口留下。

**丙：表面图算子（画进表面）**
- 弧线烘进部件表面纹理。静态、无锚点语义、不能跨部件。
  否决：那是 C 组纹理活，不是 D4。

## 四、推荐分期

- **一期（闪电弧）**：弧线段 + 中点置换生成器（主弧 + 可选分叉）
  + 单锚点 + 两端绘制 + 探针孪生对拍；条目：电弧、雷击链、
  静电火花 3 叶子。验收：编辑器与导出整包同一 t 下折线点位
  逐点一致（探针）；真机看线宽/辉光观感。
- **二期（双锚点 + 生长）**：锚点可指另一部件（连线随两端位姿
  动）；生长进度参数（藤蔓）+ 点集连线生成器（星座，点集来自
  参数化散布或标记点）。条目：藤蔓攀爬、星座连线、能量束。
- **三期（可选，事件型）**：乙路的表演级电弧（定格锚点、
  一次性），与刀光并列。

## 五、风险与不做项

- 运行时 quad 条带数量：分叉多时逐段 quad 可能上百——仍远
  小于粒子量级，但要在探针里设上限断言。
- 双锚点跨服装集/变体时锚点部件可能不存在——须点名警告 +
  降级单锚点，不静默消失（有先例口径）。
- 不做：3D 空间弧线、弧线与模拟耦合（电弧烧布料之类归 D6
  评估）、弧线碰撞。
- 线宽/端点形状（圆头/尖头）参数口径按用户既有要求带方向角。
