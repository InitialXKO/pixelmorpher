# Pixel Soul Studio 功能引入调研（research/pixel-soul-studio）

基点：main c68aa80（PR #90 压缩合并后）。调研 2026-11-22。

## 研究对象与证据边界

Pixel Soul Studio 是 B 站作者 Soulk_AI（mid 360954903）发布的付费
买断 Windows 软件：服务器校验授权码、一码一台设备。截至调研日，
它没有公开可得的软件本体——无官网、无下载页、无 GitHub、无公开
文档，作者只留了店铺名「Soulk Studio数字创意店」而未给平台与
链接，公开搜索与评论区均找不到购买入口。因此本研究没能安装实测
软件本身；对方功能侧的证据只有作者本人发布的演示视频，证据分两
级，判定里区别对待：

- **实证级**：首发演示视频《Pixel Soul Studio已正式发布》
  （BV1NNej6CEp5，2026-09-15）逐帧看过界面与操作。
- **标题级**：作者空间的后续版本视频只核实到标题、时长、播放量，
  未逐条核实画面，凡仅凭标题得出的功能在下文标注「标题级」，
  判定按弱证据处理。

pixelmorpher 侧的对照全部回源码实查，落点见各条。

## Pixel Soul Studio 侧盘点

### 首发版（实证级）

一条「高清图 / AI 生成图 → 真像素图」的转换流程，界面
（Processing Settings）可见：

- 选图（Choose Image），原图 / 处理后对照（ORIGINAL / PROCESSED）
- 模式：单张 / 批量（Mode: Single / Batch；批量只见选项，未见
  实际执行）
- 颜色数量（Color Count 滑杆；字幕称 AI 图颜色过多，可由此增减
  最终颜色数）
- 像素尺寸（Pixel Size: Auto / Manual）
- 调色板（Color Palette: Automatic / Fixed Palette）
- 输出路径（Output）
- 动作：生成预览（Generate Preview）、保存结果（Save Result）、
  送入像素编辑器（Send to Pixel Editor）

演示样本：绿色龙、犬形角色、游戏图标网格、蓝色龙、红黑女剑士。

首发简介同时声明：像素动画、本地 AI 接入、云端 AI 接入在当时属
后续规划，本地 AI 转换效果只以图片展示、未集成进正式版——这些
不算首发功能。

### 后续版本（标题级，截至 2.4.0）

作者空间视频标题依次指向：本地 AI 生成上线、像素特效库与新算法
（1.5.0）、瓦片生成器（1.6.0）、本地 AI 生成引擎升级 + 图生图
（2.0.0）、创意实验室（2.1.0）、8bit 音效制作 + 开源像素特效库
（2.2.0）、本地序列帧（2.3.0）、3D 转像素（2.4.0）；另有像素
场景风格转换、本地 AI 生成角色动画、拼豆生成、云端生成、一键
批处理等独立演示标题。以上均为标题级证据。

## pixelmorpher 侧对照与判定

### 可引入（按价值与落点排序）

1. **普通图片 → 像素画的专门转换入口（含批量）**
   - 对方：首发核心功能，实证级。
   - 我方现状：普通图片导入走 `PuppetAssetPanel.tsx` →
     `sprite-slice.ts` 的 `importSpriteFromImage`，按原图自然尺寸
     逐像素转十六进制入库，不做降采样、不做颜色量化、没有目标
     像素尺寸概念。量化零件并非没有——3D 烘焙管线
     `threejs-baker.ts` 里有中位切分量化与最近调色板映射，但只
     服务 3D 烘焙，没有接到普通图片上。
   - 判定：真缺口，且零件现成。引入形态 = 导入前加一道转换：
     目标像素尺寸（自动/手动）、颜色数量、自动/固定调色板、
     预览、批量队列、转换后直接进精灵表。复用烘焙管线的量化
     实现，不另写一份。

2. **生成式 AI 接入（本地生成 / 图生图 / 云端生成）**
   - 对方：首发时是规划，后续版本标题显示已陆续上线（标题级）。
   - 我方现状：只有 SAM 分割（`sam.ts`，本地 AI 分割，不是
     生成）；源码与依赖里没有 Ollama / OpenAI / ComfyUI /
     Stable Diffusion 一类生成式接入；插件接口
     （`plugin-api.ts`）有编辑器 API 与自定义导出器，但没有
     面向生成服务的统一提供方接口。Telea 是确定性填补算法，
     不算生成式 AI。
   - 判定：真缺口，代价最大。引入形态应是统一提供方接口
     （本地引擎与云端 API 各为一个提供方），生成结果直接进
     精灵表 / 参考图拆分链，而不是给某个服务写死一条专用路。

3. **瓦片生成器**（标题级）
   - 我方现状：只有遗留类型 `types.ts` 的 TileMap 定义，没有
     从图生成可平铺瓦片 / 瓦片集的产品链（源码里的「瓦片」
     绝大多数指运行时烘焙图格，与瓦片地图无关）。
   - 判定：真缺口，但与木偶动画主线关系弱于前两项，排第三。

4. **拼豆图纸导出**（标题级，小项）
   - 本质是一个导出器：像素图 → 拼豆色号图纸。我方导出格式
     已多（精灵表 / PNG 序列 / GIF / 视频 / Lottie / 工程 /
     运行时 HTML / Live2D），加这一项成本低，随手可做，
     不单独立线。

### 已有，不引入

- **3D 转像素（2.4.0，标题级）**：我方已有 PMX/GLB 3D 烘焙
  （多方向、纬度、变体），覆盖面比「转像素」更完整。
- **本地序列帧（2.3.0，标题级）**：PNG 序列与精灵表的导入
  导出都有；若其实指 AI 生成序列帧，归第 2 项提供方接口，
  不另立。
- **像素特效库（1.5.0 / 2.2.0，标题级）**：模式库（表面 /
  动态 / 着色，版本钉引用的 DAG 条目体系）就是这类东西且
  更深；对方的库组织方式未见超出我方之处。

### 不引入

- **8bit 音效制作（2.2.0，标题级）**：我方无任何音频生成，
  但这离木偶动画工具的定位最远；除非将来做游戏整包配套，
  否则不立项。
- **授权码 / 一码一机绑定**：是它的销售发行机制，不是产品
  功能，不在引入范围。
- **创意实验室（2.1.0，标题级）**：只有名称、无可对照的
  内容，证据不足，不立项。

## 结论

真正值得引入的只有两项：**普通图片的像素化转换入口**（零件
现成、落点明确、含批量）与**生成式 AI 提供方接口**（本地 +
云端统一接入）。瓦片生成器是可选的第三项，拼豆导出是随手
小项；其余或已有、或与定位无关、或证据不足。
