# 乙方向设计：动态三段（形变/发射/粒子）进运行时包

状态：2026-10-24 晚**重大更正**后重写。前一版的核心前提「模板只消费
发光、三段未进包」经开工前查证**不成立**——盘点漏读了
runtime-template.ts 主循环与 dynamic-src.ts：PR #38 时模板就带了
动态模式的孪生实现，三段早已进包运行。前一版的「设计」大半是在
重复设计已有之物，spike 的「移植可行性」验证亦属重复劳动。本版
按查实状态重写：现状、真实缺口（已落地两项）、待定夺一项。

## 结论先行

三段（形变/发射/粒子）在运行时包里**早已能跑**（PR #38 孪生实现
dynamic-src.ts + 模板帧循环接线）。与编辑器真正的差距只剩两处
对齐问题，2026-10-24 已落地修复：

1. **帧率没进包**：模板把粒子帧量化写死 60，编辑器按工程帧率走
   （如 8）——出生节奏/发射取整/形变调制采样全偏。已修：包加
   `frameRate`，模板改用它量化（连续钟 elapsed × 包帧率）。
2. **种子对不上**：模板种子用效果位 slot，编辑器用实例 id
   （convert 当年把 id 丢了）——同一实例两边花纹不是同一批。
   已修：convert 保留 id，模板种子改回 id；探针 L18 断言两套模拟
   同网格/同参数/同帧/同帧率/同种子下粒子逐项相等。

剩一项待用户定夺：**轮廓来源**（见「近似与待决」3）。

  12 兜底与既有口径同）；`RuntimeDynamicInstance.id` 保留并透传。
- 模板：`FRAME_RATE = EMBEDDED.frameRate || 60`（旧包回落）；
  `frameIdx = elapsed * FRAME_RATE`，`dynSimulate(..., FRAME_RATE, ...)`。
- dynamic-src：种子改 `seedKey + '|' + (inst.id || inst.slot)`
  （旧包无 id 时回落 slot）。
- 探针（verify-proc-runtime 206 → 210 项）：L15 包带帧率、L16 实例
  id 保留、L17 模板不再写死 60、L18 两套模拟多帧逐值一致（帧 30
  恰逢脉冲谷底两边同为空集，多帧断言 + 非空见证 ≥3 帧）。
- 真工程（发光工程，帧率 8）导出核查：包 JSON 含 `"frameRate":8`、
  模板接线为 FRAME_RATE 版；tsc / build / 相关探针全过。

## 近似与待决

1. **绘制层（已确认）**：两遍绘制——用户 2026-10-24 同意；且本就
   是现状。跨节点重叠时层级不逐部件精确，误差需「A 粒子飘到
   B 精灵上 + B 压 A + 粒子本该夹在中间」三条件同成立才可见；
   逐部件交错留作升级路径，不做。
2. **时钟（已确认）**：连续钟 elapsed——用户 2026-10-24 同意；
   形变本已是连续钟，粒子帧量化改包帧率后同为连续钟。两段必须
   同钟（linkToDeform 按出生时刻形变量调制发射率，L18 已锁）。
   behaviorT 方案（表演开始重置、粒子场整体重长）不取。
3. **轮廓来源（待用户重新定夺）**：用户曾拍板「照发光先例、convert
   用代表图预提取轮廓点进包」——但该拍板基于「包内无轮廓数据」
   的错误前提。查实现状是**瓦片现提**：轮廓提自实际绘制的烘焙
   瓦片，逐变体/镜像天然跟随；参数化部件连表面程序画出剪影外、
   落在瓦片内的像素也计入；与编辑器口径同义（编辑器提轮廓用的
   也是当前烘焙图）。预提取（代表图）只有一张、方向变了回落代表
   口径、与发光共担既有「代表图方向」隐患，严格弱于现状。
   助手建议改判维持瓦片现提、不预提取；已报用户，等复核拍板。
   （预提取的具体数据形状——轮廓点扁平数组 + 实心位掩码随
   __dynamic 同路、仅发射部件生成——设计已备，选它可直接开工。）
