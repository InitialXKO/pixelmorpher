# 模式库研究（research/pattern-library）

基点：main 334963df（PR #39 合并后）。本文件是研究线的盘点与问题单；
结论只认代码实查 + 探针/双路比对证据，标「待核」的不得当结论引用。

## 现状盘点（2026-10-24 代码实查）

代码里有两套并行的「模式库」，先分清：

### 一、静态表面模式库（表面 DAG）

- `src/lib/proc-runtime/pattern-templates.ts`（510 行）：25 个内置模板
  （自然 11、重复 9、着色 3、工业 1、基础 1：鳞片/墙砖/蜂窝/锁子甲/木纹/
  水面/大理石/迷彩等）。模板 = 一张 SurfaceGraph + 参数定义；参数经
  graph.params 注入，节点参数以 `$key` 引用。
- `src/lib/proc-runtime/surface-ops.ts`：49 个算子规格（SURFACE_OP_SPECS，
  含分类、作用域与画布布局）。
- `src/lib/proc-runtime/pattern-library.ts`：用户模板与内置同格，存
  localStorage（键 pm-user-patterns-v1）；存模板时参数定义优先沿用来源
  模板，无来源时按 graph.params 现值自动生成（deriveParamDefs，经验区间）。
- 编辑器：SurfaceGraphEditor + SurfaceGraphCanvas（画布 + 作用域框）。
  入口在 ParametricAppearanceEditor「模式库（DAG 模板）」节：选模板、
  调参数、存我的模板；启用后烘焙优先走 DAG，旧层程序留作回退。
- 消费两路：编辑器侧经参数化外观烘焙进精灵；convert 也把 surfaceGraph
  带进运行时包，包内有部件 program/graph 求值路径。

### 二、动态模式库（四段参数化预设）

- `src/lib/dynamic-patterns.ts`（612 行）：模板 = 形变段 + 发射段 + 粒子段
  + 发光段（一整套 DynamicPatternParams）。使用模型与静态库一致（内置
  模板 + 滑杆调参 + 我的模板）。双挂载：节点（角色固有）或服装件（随
  服装集生效）；解析按「效果位 slot」合并——服装件同位替换节点实例、
  同位「关闭」压掉节点实例、不同位叠加。
- `src/lib/dynamic-pattern-sim.ts`：粒子模拟纯函数——粒子集合只由（实例、
  精灵、帧、帧率、种子）决定，确定性、任意帧可直接求值。
- 编辑器：DynamicPatternEditor（556 行），挂 RigPanel 与
  ParametricAppearanceEditor。
- 消费：主画布渲染（形变叠加层、节点本地粒子绘制层、发光选区提亮）。
  运行时包只接发光段（乙案：掩码 + 印章 stamps 在包内重算，与编辑器
  glowStamp 逐式对应）；形变/发射/粒子三段不进包。

## 待核问题（研究第一步先核这些）

1. 动态「我的模板」存哪、与静态库是否共享存储与命名空间？
2. 静态表面图双路一致性：编辑器烘焙与包内求值，同一张图同一参数，
   结果是否逐像素一致？（抽 2–3 张模板图双路比对）
3. 49 个算子里哪些没有任何模板在用（死算子）？25 个模板里哪些参数
   从未被 `$key` 真引用（死参数）？
4. 动态四段在主画布的接线是否全通（按五段审计口径：按钮→store→
   渲染调用→渲染函数内判断→数据源）？发光段已有运行时对应，其余三段呢？
5. glowAngleSpace 缺省冲突（承前悬置）：辉光方向铁律说默认世界，
   落地缺省是 sprite——动态库与包内两处各用的哪边？
