# 模式库按 DAG 分层组织：动态图化 + 版本钉定

状态：**已定稿**（2026-10-24 晚用户审过，未决三点全按本稿：
段冲突点名拒绝、条目删除统一为拒绝、内置拆一个样板）。实现中。
已拍板的前提：

- **动态图化**（用户令）：父模式本质上是多个子模式的模式化配合，
  子模式可用在多个父模式——引用关系成 DAG，不退化成树（沿用
  方向甲第一铁律）。
- **共享语义用版本号解决**（用户令）：引用钉版本、改定义出新版、
  升级是显式动作；不搞「全网自动跟着变」，也不搞「引用即快照」。
- **升版时机**（助手倾向、用户准）：草稿制——编辑皆草稿，点
  「发布新版」才 +1。
- **管辖范围**（助手倾向、用户准）：一库一规——动态模式与表面
  子图 ref 同受版本纪律。
- 分层口径（同日晚定案）：模式库只收逐帧算像素/场的变换；时序
  归编排、层级归结构、接缝归著者，不入库。

## 一、统一条目模型

库条目 `LibraryEntry`：

```ts
{
  id: string;              // 稳定身份，改名不断链（同现行子图 id 口径）
  kind: 'surface' | 'dynamic';
  name: string;
  cluster: string;         // 货架分组（沿用现行 cluster）
  versions: Record<number, EntryDef>;  // 已发布版本，发布后不可变
  draft?: EntryDef;        // 至多一份草稿（编辑中未发布状态）
  latest: number;          // 最新发布版本号，从 1 起
}
```

- `EntryDef`（surface）= 现行 `PatternTemplate` 的 { params, graph,
  outputs }；`EntryDef`（dynamic）见 §三。
- **已发布版本不可变**是整套纪律的根：同一 `id@版本` 在任何时候、
  任何安装上必须同内容。展开缓存因此天然稳定（表面侧缓存键仍用
  展开后 JSON，不变）。
- 内置条目随应用出厂（全部 v1 入库）；应用升级只许**追加**版本
  或新条目，不许改写已发布版本。
- 用户条目存本地存储（现 `pm-user-dynamic-patterns-v1` 等升级为
  统一条目存储，迁移见 §六）。

## 二、引用钉版本

- 表面 `ref` 算子：`params.ref` 由模板 id 改为 `id@版本`。
- 动态父模式对子模式的引用：`{ entry: id, version, overrides }`。
- 宿主挂载引用条目时同样钉版本（节点/服装件上的动态实例、表面
  图挂载点）。
- 存量无 `@` 的 ref：读取时按该 id 最新发布版解析，并给一次性
  迁移提示，下次保存写成显式 `id@版本`。禁止新增浮动引用。
- 悬空引用（id 或版本不存在）：展开期点名 + 该引用展开为空，
  沿用现行未解析口径，**不许静默回退最新版**。

## 三、动态图化：父模式 = 子模式 + 配合边

**子模式**（dynamic 的叶子 def）：

```ts
{
  segments: Partial<DynamicPatternParams>,  // 只写它管的段的键
  expose: (keyof DynamicPatternParams)[],   // 参数口：可被覆盖/接线的键
}
```

子模式通常只管一段（形变/发射/粒子/发光之一）；写了哪些键决定
它管哪段。参数口之外的键是内部定死，父模式不可覆盖、不可接线
——封装边界。

**父模式**（dynamic 的组合 def）：

```ts
{
  children: { entry: string, version: number,
              overrides: Partial<DynamicPatternParams> }[],
  coordination: CoordinationEdge[],
}
```

父模式可以被另一个父模式当子模式引用（递归组合；层 = 引用
深度，不预先行政分层）。

**配合边**（封闭集合，只三种；都是对现有耦合的泛化）：

- `modulate` 调制：`{ from: 子模式.段量, to: 子模式.参数键, depth }`
  ——量源 v1 只认段脉冲量（形变 amount、发光 pulse；现行
  `linkToDeform` 是它的特例）。
- `phase` 相位：`{ base: 子模式, offsets: { 子模式: 圈数 } }`
  ——共享基准相位 + 各自偏移（现行各段 phase 字段是它的散装形）。
- `followParams` 跟随：`{ leader: 子模式, follower: 子模式,
  keys: 参数键集 }`——follower 的这些键跟 leader 走（现行
  `glowFollowGroup` 是它的特例）。

配合边只许落在参数口内的键上。追随段（`follow*` 参数）是对
**外部部件**的引用，不是配合边，位置不变（同日晚定案）。

## 四、展开规则

**动态展开**：父模式 → 递归解析 children（`id@版本` 取 def，
组合 def 继续展开）→ 叶子参数按段合并 → 配合边折成扁平参数
（调制折为 linkToDeform 类字段、相位折为各段 phase 字段、跟随
按 leader 参数回填 follower 的键）→ 产出现行扁平
`DynamicPatternParams`，走现有 `resolveDynamicPatterns` 与孪生
求值，**求值层零改动**。

- **按实例去重**：同 `(id@版本 + 有效 overrides)` 在同一父模式
  内多次引用只算一份；overrides 不同 = 不同实例，各自保留。
- **段冲突**：两个叶子子模式写同一段同一键 = 配合错误，展开期
  **点名拒绝**，不许静默覆盖——父模式作者须用 overrides 或配合
  边显式裁决。（本稿自定，请审：备选是后者覆盖 + 警告。）
- **环检**：展开栈按条目 id 判环，跨版本同 id 亦算环（A@1 引 B、
  B 引 A@2，展开 A@2 时 A 已在栈中），点名拒绝，沿用
  graph-expand 现行口径。

**表面展开**：现行 `expandSurfaceGraph` 不变，只多一步 ref 的
版本解析（`id@版本` → 该版本 def 的 graph/outputs）。

## 五、版本治理（编辑器行为）

- **反向索引**：扫全部条目 def 得出（谁钉了 `id@某版本`）。编辑
  条目时展示影响面：被几个父模式/挂载钉住、各钉哪版。
- **升级动作**：引用方编辑界面列出「钉住版本 < 最新版」的引用，
  可逐个选目标版本升级。升级只写引用方的**草稿**——已发布父
  模式里的钉定永不被动改变，子模式出新版后，父模式必须发自己
  的新版才吃到。
- **回收**：版本被任何已发布版本/草稿/挂载钉住 → 不可删；未被
  钉住且非最新版 → 可删（编辑器提供清理清单，手动删，不自动）。
- **条目删除**：仍被钉住时**拒绝**并列出钉住方。（本稿自定，
  请审：现行子图删除是「走未解析路径」，与「已发布不可变」
  冲突，此处统一为拒绝。）

## 六、迁移

- 内置动态模板（现 9 个）→ dynamic 条目 v1：以「叶子条目」入库
  （def = 全参数 segments、expose = 全部键），不强行拆子模式；
  拆分是后续作者行为（样板问题见未决 3）。
- 内置表面模板（`PATTERN_TEMPLATES`）→ surface 条目 v1；存量
  ref 按 §二存量规则。
- 用户动态模板（localStorage 旧 key）→ 迁移为用户条目 v1，
  旧 key 保留一代做回滚。
- 存量挂载实例（节点/服装件上存整份 params 的
  `DynamicPatternInstance`）→ 视为**内联实例**继续工作，
  `resolveDynamicPatterns` 不变；编辑器提供「存入库」动作：把
  内联参数发布为条目 v1，实例改成钉版本引用。渐进迁移，不做
  一次性全量改写。

## 七、明确不做

- 求值层零改动：四段孪生（`dynSimulate`/`dynamicDeformAt`）、
  运行时包格式、表面求值器都不动；包内仍是展开后的扁平形，
  包不带版本图。
- 动态配合边不引入任意数据流图（不把表面 DAG 搬过来）；配合
  边只有三种，封闭集合。
- 不做跨工程/云端库共享；版本是本地库纪律。
