# 方向甲设计：子图实例化（DAG 分层封装）

状态：研究设计（2026-10-24，用户定方向甲）。范围 = 静态表面 DAG；
动态模式库无图结构，不在本文范围。

## 第一条铁律：不许把 DAG 退化成树（用户令）

封装的朴素实现是「宏展开」：每个引用点塞一份子图拷贝。这会把图
变成树——同一子结构被多处引用时层层复制，嵌套引用指数膨胀；
同一子场被反复求值；副本各自漂移。现行平图里「一个节点扇出给
多个消费者」正是 DAG 相对树的全部价值，封装不得以它为代价。

故本设计的展开按**实例**去重、不按**引用点**复制：

- 实例 = （模板 id，有效参数集）。同一实例被多少个引用点、以
  多少种输出被消费，展开后只保留**一份**节点集；引用点本身在
  展开图中消失，消费边直连共享节点——扇出结构原样保留。
- 展开产物仍是 DAG：节点数随「不同实例数」增长，不随「引用
  次数」增长。这一点由 spike 的节点计数断言把守（S2/S7）。

## 数据模型（存储层，带 ref 的图才是常态）

- 新算子 `ref`：params = `{ ref: <模板 id>, out: <输出名，缺省
  'main'>, ...覆盖 }`。无字段输入口（v1）——子图的环境叶
  （inside/dist/cell* 等）读实例化位置的上下文（上下文穿透，
  与现行平图「同一节点被作用域内外共用」的求值语义一致）。
- 模板新增可选 `outputs: Record<string, string>`（输出名 → 子图
  内节点 id）。缺省 `{ main: 首条写出的 from }`——存量模板零改
  动即可被引用（写出源即主输出）。
- 引用按模板 **id**（内置 id 稳定；用户模板 id 为 `user-*`；
  改名不断链，删除走未解析路径）。
- 有效参数链：模板参数定义缺省值 → 模板 graph.params →
  ref 节点覆盖。覆盖值可以是数字，或 `"$外层键"`（转发引用方
  图的参数）。子图内部一切 `$` 引用只认自己的有效参数——封装
  边界即参数作用域边界，外层同名参数不漏入（现行求值器的单层
  graph.params 正是靠展开代入来分层的，见下）。

## 展开语义（烘焙期图变换，求值器零改动）

存储的图永远带 ref；展开只发生在两个烘焙入口，共享同一纯函数
`expandSurfaceGraph(graph, library)`：

1. 编辑器烘焙（main-canvas buildParametricSprite 入口，克隆图
   展开后走原三路烘焙）；
2. convert 进包（appearanceToBase 写包前展开，警告汇入包
   warnings；运行时模板拿到的永远是展开后的平图，零改动）。

展开规则：

- 逐图处理：非 ref 节点按当前命名空间（根图为空、实例为
  `i<k>:`）加前缀复制，输入边在图内重映射；节点参数中的 `$`
  引用按**来源图的有效作用域**全部代入字面量（展开图
  params 清空）——求值器的单层参数表因此不会串扰。
- ref 节点：解析目标模板 → 算有效参数 → 查实例池：命中则
  直接把本引用映射到池中该实例的输出节点；未命中才展开
  目标图（其内部 ref 递归同理，实例池全局共享——跨层级的
  同一实例同样合并）。
- 环：实例化栈已含目标 id → 点名警告 + 该引用替换为零场
  const 节点，不挂死。深度另设上限兜底。
- 未解析（模板不存在/已删）：点名警告 + 零场，同上（循发光
  「无代表图点名」先例，不静默、不阻断整包）。
- 写出：只有根图的 writes 进展开图（按根图映射重写 from）；
  子图的 writes 只用于缺省输出推导，不产生写出。

库解析：library = 内置模板 + 用户模板。编辑器侧实时读；
convert 侧由调用方把库快照经 opts 传入（同 SpriteTable
「工程级表由调用方传」的先例），convert 本身不读 localStorage。

## 编辑器

- ref 节点在节点行/画布中显示为：目标模板名 + 输出选择 +
  覆盖参数行（只列目标的暴露参数，可数字/可 $ 绑定，与现行
  参数三态编辑同口径）。算子规格表加 `ref` 一条（分类「引用」），
  参数面动态生成，渲染处特判（现行参数 UI 是规格驱动的静态表）。
- **范围叉（待用户拍板）**：「打包成子图」动作——框选若干节点
  → 存为命名子图模板（选定边界节点为输出、暴露参数）→ 原选区
  替换为 ref。是封装的作者侧入口；不做它，v1 的子图来源只有
  既有模板与整图另存。建议 v1 先落语义与引用侧（数据模型、
  展开、烘焙/进包 parity、探针），打包动作紧随其后（数据模型
  不因此返工）。

## 与既有口径的关系

- 模板整图应用不变（顶层图可含 ref，应用时克隆的是带 ref 的图，
  烘焙时展开——模板从此可以引用模板，库获得层次）。
- 25 个内置模板零迁移：outputs 缺省规则覆盖；想被多输出引用
  的模板（如鳞片）再补声明 outputs 即可。
- 烘焙确定性：展开是纯函数、实例编号按首次遇见序，产物稳定；
  探针以「展开烘焙 == 手工平图烘焙」逐字节断言把守。

## Spike 证据（2026-10-24，spike-subgraph-check.mts，14 项全过）

展开原型（按实例去重）对真实模板（鳞片）验证：

- 无 ref 图展开 = 恒等（烘焙逐字节不变、节点数不变）；
- 宿主图以 3 个 ref（同实例、main/shadow/edge 三输出）复现鳞片
  全部写出，烘焙与鳞片原图逐字节一致；展开节点数 12 = 宿主 1 +
  鳞片 11（朴素宏展开将是 1 + 3×11 = 34）——**没有退化成树**；
- 参数覆盖生效且等值于原图改参数（cw=14 逐字节）；三处覆盖其一
  不同值时实例正确分裂为两份（参数不同 = 不同场，本就该分裂）；
- `$` 转发（宿主参数 $w → ref 的 cw）等值于字面覆盖；
- 环（模板自引用）被点名、展开终止、产物可烘焙；未解析引用
  点名 + 零场可烘焙；
- 嵌套（B 引用鳞片、宿主同时直引鳞片与 B）：跨层级同一实例仍
  合并为一份（节点数与手算一致）。
