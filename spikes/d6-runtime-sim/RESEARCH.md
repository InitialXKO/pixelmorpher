## 一、现状盘点（代码实查）

D6 一、二期与毛发已按立项文档（`spikes/simulation/PROPOSAL.md`）的
**甲路（作者期烘焙）**全包落地，乙路（运行时有界状态）在立项时只留
口不开。三期（烟/流体/刚体）已评估收口：烟走 D1 动态表面、流体与
刚体明确不做。本节只盘与「实时化」相关的家底：

**求解器（`src/lib/sim/`，共 583 行）**

- `verlet-chain.ts`：Verlet 链求解器 `solveVerletChain`——**批量纯
函数**：给定逐帧钉点（链根世界位）、逐帧段长（由参考姿态 FK 给
出，容忍驱动自身伸缩）、初始关节位与参数，一次算出全窗关节位。
积分（重力/风/阻尼）→ 距离约束迭代（自钉点向外）→ 逐帧推进，数
学形态与帧序都已是「逐帧步进」，只是被包在批量接口里。
- 参数体系 `ChainBakeParams` = { gravity 980 px/s²， windX，
damping 0..0.2（默认 0.02），iterations 1..24（默认 8）}，链/布
料/毛发三处共用同一套。
- 烘焙折算：解出段向相对参考段向的世界增量 → 折回各节点本地角
（基准 + 本节点增量 − 父节点增量，末节点刚性延续），写 angle 轨
道关键帧。播放端（编辑器预览、导出运行时）零求解器、逐帧纯函数。
- `cloth-bake.ts`：布料 = 平行链（列）+ 横向/剪切约束，顶行多钉
点；同一折算、同一参数、同一指纹。`strand-bake.ts`：毛发 = 多条
独立链的组织层（扇形生成 + 整束烘焙 + 聚合新鲜度），不新增求解器。

**指纹新鲜度机制**

- `chainBakeFingerprint`：链结构 + 参数 + 帧窗 + 参考关节采样
（0.5px 量化）的 FNV 哈希，存进 `Character.chainBakes` /
`clothBakes` 档案；`isChainBakeFresh` 重采样重算比对，过期面板
点名（不静默沿用）。这是甲路的命门管理：驱动改了必须让作者知
道旧烘焙已作废。代价也在这里——**调参/改驱动 → 重烘 → 再看**，
迭代是断续的；且烘焙只对烘焙时那条时间线成立。

**烘焙路线的固有边界（实时路线的立项理由）**

1. 运行时才知道的输入进不来：状态机分支、交互、以及 PR #55 钳制
锚定在运行时对物理体的 Δ 回写——根位姿被运行时改写后，烘焙时
按作者根运动算出的链摆曲线与真实根运动脱钩，链会「按旧轨迹
摆」。这是本调研最硬的动机：钳制落地之后，烘焙与运行时根运动
的不一致从理论问题变成了现行问题。
2. 预览迭代断续：改驱动/参数要重烘才见效（指纹过期点名是防呆，
不是体验）。
3. 竞品对照：Motion2D 的弹簧物理是运行时实时的（播放器里头发/
裙摆实时跟随，见 PR #56 调研），本项目与它的差距点正在于此。

**现成先例：钳制锚定（PR #55）的状态确定性形态**

- 会话层 `src/lib/clamp-session.ts`：每角色一份步进状态 + 每片段
起点的状态快照缓存；纪元 = 角色对象身份（编辑即换对象 → 整表
失效重建）；顺序播放逐帧步进，scrub 跳帧 = 取片段起点快照顺演
到目标帧。状态步进 `stepClampState` 只读平结算位
（`computeWorldTransforms` 无 ctx 的结果），与求值解耦、可独立
预演。
- convert 侧 `sampleWindow` 带状态采样：整窗顺序步进、窗口起点留
快照、片段窗从快照起算，`steppedClampState` 提供从零步进的独立
入口（探针/导出共用）。
- 运行时模板侧锚定遍：模块级状态 Map、录制/回放起点清状态、遍的
位置在帧求值序内（部件循环后、粒子前），Δ 回写物理体后同帧后
续阶段读到的就是回写后位置。

## 二、Spike 实证（`spike.mts`，14 条断言全过）

Spike 做的事：把 `solveVerletChain` 的同一数学改写成**有状态增量
步进器**（状态 = 每质点 x/y/px/py；单步函数 = 钉根 → 积分 → 约束
迭代），外加一个仿 clamp-session 的最小会话层（片段起点快照 +
顺演/scrub 重演）。驱动点是闭式正弦轨迹（模拟作者动画给出的链根
逐帧世界位），链 8 点 7 段、参数取 `defaultChainBakeParams()`。

| # | 断言 | 结果 |
|---|---|---|
| ① | 同快照两轮独立步进 120 帧 | 状态与关节位**逐位一致** |
| ② | 跳回第 120 帧（快照重演）== 连续步进到 120 帧；播过头再跳回仍一致；独立会话重演亦同 | **逐位一致**（含 px/py 速度分量） |
| ③ | 活状态步进 90 帧后片段起点快照逐位未变 | 成立（深拷贝纪律） |
| ④ | 3600 帧（60 秒）长程步进 | 全程有限不发散；段长误差有界且**无随时间增长**（后窗 6.07% ≤ 前窗 6.56%）；链尾累计行程 14667px（确实在动） |
| ⑤ | 步进器步进 150 帧 vs 产品 `solveVerletChain` 批量结果 | **逐位一致**——实时路线不需要第三份求解器，数学可直接复用产品代码 |
| ⑥ | 单链每帧步进耗时 | **约 8–11µs/帧**（8 点、迭代 8，两轮测量）；线性外推 20 条链 ≈ 0.2ms/帧 |

两条必须如实标注的实测边界：

- ④的段长残差：在本夹具的**压力工况**下峰值 6.56%（迭代 8）。压
力来自夹具本身——自由质点终端速度 ≈ g·dt²/(1−damping) ≈
13.6px/帧，与段长（9–14px）同量级，远超真实角色根运动的常规
幅度。残差随迭代次数近似反比下降（同驱动实测：迭代 2 → 27%、
4 → 13.8%、8 → 6.6%、16 → 2.6%、24 → 1.4%）。结论：稳定性成
立（有界不增长），精度是「迭代次数 ↔ 成本」的旋钮，不是发散
问题。
- Spike 的驱动是合成闭式轨迹，**没有**接进真实角色的
`computeWorldTransforms` 平结算通道取根位——编辑器落点一节的
驱动接法是照 clamp 的 `stepClampState` 先例推演的，未实测。

## 三、实时路线设计

### 3.1 状态形态与快照口径（复用点与差异，逐项对 clamp）

| 维度 | 钳制锚定（已落地） | 实时模拟（本设计） |
|---|---|---|
| 状态内容 | 每锚一个冻结位或 null（离散、极小） | 每链一组质点 (x,y,px,py)×N（连续浮点数组） |
| 状态存在性 | 事件触发才有 | 链活着就有，依赖片段起点以来的全部历史 |
| 步进输入 | 平结算的锚点世界位（只读） | 平结算的**链根世界位** + 快照时冻结的段长 |
| 快照粒度 | 片段起点 | 片段起点（同） |
| 失效纪元 | 角色对象身份（同） | 角色对象身份（同）；另加模拟定义（链根/参数）变更——已包含在对象身份内 |
| scrub 重演成本 | 每帧一次完整 FK（重） | 每帧每链约 10µs（轻）——**比重演钳制便宜两个量级** |
| 快照克隆成本 | 小 | O(链总点数)，仍属小额 |

复用结论：`clamp-session.ts` 的会话结构（纪元 + 片段快照 Map +
顺演/scrub 分支 + `steppedXxxState` 独立入口）可近乎照搬为
`sim-session.ts`；要新写的只有步进器本体（spike 已证其与产品数
学逐位同）和「段向增量 → 本地角增量」的逐帧施加（折算公式现成，
在 `bakeChainSwing` 里，抽成逐帧 override 即可）。

**与烘焙口径的一个实质分歧（须点名）**：烘焙的段长逐帧取自参考
姿态——链节点自身的 x/y 轨道与拉伸会逐帧改变段长；实时版在快照
时冻结段长（常长），链节点自身的平移/拉伸动画不再影响段长（角
度仍由模拟接管，与烘焙同）。根驱动则无分歧：链根关节世界位只由
祖先决定，烘焙参考与平结算在该点上恒等。接受常长 = 接受「链节
点不要再兼职拉伸动画」这一作者约束，换取步进输入只需根位一点。

### 3.2 编辑器预览落点

- 新增 `src/lib/sim-session.ts`（仿 clamp-session）：编辑器渲染
时，`renderUnified` 的调用方在已有平结算 pass 后步进模拟状态，
把链节点的段向增量经 ctx 注入 `computeWorldTransforms` 施加
——与钳制 ctx 同一条注入通道（钳制在结算后施加 Δ，本项在结算
后施加角增量 override），两遍的先后：模拟先于钳制（钳制的触
发判定应看模拟后的位姿，与「结算后施加」的现有口径自洽）。
- 驱动的平结算 pass 编辑器本来就在为钳制步进而跑（无钳制时主画
布是否已有平 pass 需落地时核对；没有则模拟自带一次，成本是全
角色 FK 一遍——这是编辑器侧最重的一笔经常性成本，量级同钳制
会话的现有开销）。
- UI：RigPanel 链摆区加「实时预览」开关与归属选择（同一链根二选
一：烘焙档案 / 实时定义），参数共用 `ChainBakeParams` 不另立。

### 3.3 convert / 运行时包落点

- 包内只发**定义**不发曲线：链根节点 id、参数、段长（快照口径的
静止段长）、基准本地角。包体积增量每链百字节级。
- 运行时模板新增模拟遍：位置在帧求值序的**位姿阶段**（部件位置
计算之前）——与锚定遍不同，锚定是整角色平移、可在部件后回写；
模拟改的是关节角，必须先于部件落位。此落点是推演，落地时须对
照模板位姿阶段的实际结构核对（本调研未逐行读模板位姿段）。
- 运行时状态口径照锚定遍：模块级状态、表演开始/录制/回放起点从
片段起点快照初始化；**定步长 = 包内帧率**，禁止按墙钟积分（确
定性口径）；宿主掉帧时的补步/跳步策略须先定（见裁决 6）。
- 孪生与对拍：编辑器步进器（TS）与模板步进器（模板内 JS）是两
份同语义实现——与钳制（`stepClampState` vs `runAnchorPass`）、
像素链（PIXEL_SRC 孪生）同一种维护形态，已有
`verify-clamp-runtime` 式「抽模板代码驱动对拍」的探针先例可照
搬。跨引擎逐位一致性注记：`Math.hypot` 末位实现定义，跨浏览器
可能差 1ulp——视觉无感，跨宿主回放不承诺逐位、只承诺同宿主确
定性（与锚定遍现状口径相同）。

### 3.4 与烘焙路线的分工建议

| 场景 | 建议 | 理由 |
|---|---|---|
| 编辑器内调链摆/毛发的手感 | **实时** | 免重烘迭代是指纹机制下最痛的一环；spike 证成本可忽略 |
| 运行时根位姿会被改写的角色（钳制锚定、状态机大幅位移、物理 Δ 回写） | **实时** | 烘焙曲线与真实根运动脱钩（§一边界 1），实时以真实根位驱动恒自洽 |
| 交互宿主（桌宠、网页演示、WASD 类） | **实时** | 输入不在时间线上，烘焙无从算起——这正是乙路立项时「能响应运行时输入」的收益项 |
| 布料片 | **继续烘焙** | 点/约束数比单链大一个量级，实时孪生与对拍成本陡增；且布料化身靠挂精灵、作者期迭代痛点小于链。本调研 spike 只证了链，布料实时无实证 |
| 长叙事片段、确定性交付优先的内容 | **继续烘焙** | 烘焙产物是死数据，任何宿主逐位同结果；实时只在同宿主内确定 |
| 低端宿主/大批量角色同屏 | **烘焙**（或按链数设实时上限） | 实时成本随链数线性涨，烘焙为零 |

一句话：**链/毛发走实时（预览先行、运行时随后），布料与叙事内
容继续烘焙，两条路在同一参数体系与同一链定义下共存、按链根二
选一。**

## 四、三期流体结论（一句）

**维持不做**：立项 §七的尺度论证（几十像素部件下 FLIP 网格无物
理意义、SPH 成本与观感严重不配）不因求解器搬到运行时而改变，
实时化只会再叠每帧成本与跨宿主确定性问题；烟的观感已由 D1 动
态表面覆盖，此结论不因乙路开启而重开。

## 五、代价分项

- 编辑器：`sim-session.ts`（仿现成结构，约 150 行量级）+ 逐帧角
增量 override 的 ctx 接线（折算公式现成）+ 平结算 pass 复用/
自带 + RigPanel 开关 UI。中等。
- 包与运行时：Character 侧实时定义字段 + convert 发包 + 模板步
进器一份 + 对拍探针一份。中等偏上，主要在孪生对拍。
- 性能：spike 实测单链约 10µs/帧；角色级（≤20 链）约
0.2ms/帧，编辑器与桌面运行时无压力；低端移
动宿主未测，需设链数/点数上限兜底。
- 长期维护：两份求解器孪生（与钳制/像素链同级成本，已有探针形
态可压住）；「常长」作者约束需写进面板文案与文档。

## 六、待用户裁决

1. **乙路开不开、开多大**：只开编辑器预览（低风险、立即解决调
参迭代痛点），还是一步到运行时包（解决钳制 Δ 脱钩与交互宿
主）？本文建议分两步但同一期立项：预览先行、运行时紧随（孪
生只写一次、两边共用会话语义）。
2. **对象范围**：链 + 毛发进实时，布料不进（§3.4）——是否认同？
3. **常长口径**：接受「链节点不再兼职平移/拉伸动画」这一作者约
束，换步进输入只取根位？
4. **与烘焙档案的互斥粒度**：按链根二选一（本文建议），还是允
许烘焙打底 + 实时残差叠加（复杂度显著更高，不建议）？
5. **默认开关**：编辑器打开工程时实时模拟默认开还是默认关（开
= 预览进入有状态飞地成为常态；关 = 延续现状、按需开）？
6. **掉帧策略**：运行时宿主掉帧时按包帧率补步（保确定性、可能
螺旋）还是跳步到当前帧（保流畅、状态与标称时间线脱钩）？

## 七、未验证与边界（如实清单）

- Spike 驱动是合成轨迹，未接真实角色 FK 通道取根位；编辑器平
结算 pass 的复用细节（无钳制时是否存在现成平 pass）未核对。
- 运行时模板位姿阶段的实际结构未逐行读，§3.3 的模拟遍落点是按
锚定遍先例的推演，落地前须对模板代码核对一遍。
- 布料实时化无 spike 实证（点数/约束规模、scrub 重演成本均未
测），§3.4 的「继续烘焙」是基于成本量级的判断而非实测否定。
- §一边界 1（烘焙与钳制 Δ 脱钩）是机制推导，未构造复现用例实
测脱钩幅度。
- 耗时数字来自本机 bun（V8/JSCore 环境与浏览器同量级参考），未
在浏览器与移动端真机测。
