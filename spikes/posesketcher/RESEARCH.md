# PoseSketcher 调研：与本项目的区别与可借鉴之处

对象：https://github.com/gladpax/PoseSketcher （本地克隆 `~/workspace/scratch/posesketcher`，2026-10-27 实读源码）
方法：对方仓库全量源码实读（约 3,500 行）+ 本项目对应面代码勘察（unified-render / PixelCanvas / 向导 / 蓝图模板）。
许可证：**Apache-2.0**（代码与数据同证，无单独素材条款、无资产文件）。借鉴代码/常数表在许可证层面无负担，保留声明即可。

---

## 一、它是什么

给画师的**笔触驱动 2D 人体姿态起稿工具**：在空白处划一根线生成躯干+头（主轴即标尺），再从肩/髋关节点起笔划四根线、四肢按比例自动切出肘腕/膝踝，拖关节点微调，最后导出 PNG 拿去当绘画参考。纯静态、无动画、无场景存盘（刷新即丢）、无姿态预设。React 19 + TypeScript + Vite，渲染是纯 SVG 体块（胶囊形），5 个提交同日倒入的原型项目，无测试。

## 二、与本项目的根本区别

| 面 | PoseSketcher | pixelmorpher |
|---|---|---|
| 定位 | 绘画参考起稿（一次性静态图） | 木偶动画工具：建角→绑骨→编排表演→导出可播放运行时包 |
| 人物模型 | 扁平 2D 绝对坐标点集，**没有骨骼树、没有角度**（只有头有 headAngle），关节点就是一堆 Point 字段 | 骨骼树 + 真 3D FK/IK、Socket 静态解剖 + Transform 动态姿态、三维烘焙管线 |
| 姿态操纵 | 直接拖点 + 手写平移传播（拖腰弯躯干的权重函数），无 IK | IK 乙案真 3D 求解 + 蓝图/行为/状态机编排 |
| 比例来源 | 用户那一笔的长度（笔长相对标尺：主轴长 = 3 单位 = 头 1 + 躯干 2），四肢长也由笔决定、只按比例切关节 | 3D 模型烘焙决定，或手绘精灵既成事实；比例不是可调参数 |
| 动画 | 完全没有（无时间轴、无关键帧） | 完整：关键帧片段、表演、行为树、状态机、逐帧运行时 |
| 持久化 | 场景不能存盘；只有「比例蓝图」JSON 可导入导出 | 工程文件 + 运行时包 + 模式库条目版本体系 |
| 渲染 | SVG 胶囊体块（半径公式 + 切线连接） | 像素精灵 + WebGL 图集/蒙皮/堆叠/发光 |
| 视图 | 正面 + 「侧面」（肩髋横向距 ×0.2 的假透视），无 3D | 八方向 + 纬度烘焙 + 真 3D 位姿 |
| 五官 | **完全没有**（头是一个贝塞尔蛋形） | 精灵自带 + 转面 yaw/pitch + 参数化外观 |

一句话：两者只在「人体比例」与「姿态」两个词上相邻，工程形态几乎正交——它没有一样东西能整块搬进来，能借的全是**数据、公式与交互点子**。

## 三、逐方面判定

### 1. 节点无精灵时的兜底 ——
- 它的做法：任何姿态都有一套胶囊体块渲染（两点+两半径的切线连接体），关节半径有成套公式（躯干约 0.45·s、髋 0.28·s、颈 0.20→0.15·s、肘 0.15·s、腕 0.11·s，各关节另有倍率表 JointScales）。
- 本项目现状：主渲染里没精灵的节点直接跳过不画（unified-render 实读：resolveSprite 为空且非纯堆叠件 → continue），编辑期只有骨骼线框；向导新建角色、拆分中间态、精灵被删等阶段都是「有骨无形」。
- 判定：借它的**体块半径公式与胶囊画法**，驱动源换成自家骨骼世界变换——本项目已有 jointWidth（关节盘直径）数据可作半径首选来源、缺失时落公式默认值。落地形态：编辑器渲染加一档「人偶兜底」——节点无精灵时按骨骼链画胶囊人偶（跟随当前姿态/动画），运行时包不带（编辑辅助）。这是它对本项目最实在的一项。

### 2. 快速搭建 ——
- 它的做法：一笔生成躯干（沿笔触弧长按比例落头/颈/腰/肩/髋落点，笔可以是弯的），四笔生成四肢（起笔点热区吸附到肩/髋，笔长按比例切关节）。
- 本项目现状：建角靠 3D 模型烘焙或逐个手建节点；没有 2D 徒手起角路径。
- 判定：生成算法（弧长落点 + 比例切分 + 吸附）可直接参考，做成「画一个火柴人 → 生成骨骼节点树（含初始比例）」的向导模式，补上纯 2D 手绘角色的入口。工作量在向导与生成骨架的口径对齐（Socket/offset3D 语义），不是抄代码量级。

### 3. 精灵绘制比例参考 ——
- 它的做法：比例蓝图是一份可导入导出的 JSON（脊柱落点比例、肢内切分比例、关节粗细倍率、基础色），另有 A-pose 可视化编辑器拖着改。
- 本项目现状：PixelCanvas 已有参考图垫底（URL + 不透明度），但垫图要用户自己找图；没有「按人体比例生成的标准垫图」。
- 判定：比例常数表（附录 A）可直接引入，生成一档内置垫图：按目标精灵尺寸渲染标准比例人偶（正面/侧面）垫在画布下，用户照着描/对比例。数据是 Apache-2.0 的几十个数，成本极低。

### 4. 五官对位 ——
- 它没有五官：头是蛋形路径，只有 headCenter、headAngle、长半轴 0.5·s / 宽半轴 0.35·s、头顶距颈 0.9·s 这组头部几何量。
- 判定：五官点位、眼鼻嘴对位它一概没有，别指望。唯一可借的是头部几何量——若将来做「头部对位参考」（画头时垫头颅蛋形 + 朝向角指示），这几个数可用。本项结论以「无」为主，列此防误期待。

### 5. 姿态预设 ——
- 全仓无任何内置姿态（站立/行走都没有），姿态只能现画。所以「借它的姿态库」不成立。
- 但它的**一笔画姿态**交互对本项目有启发：用户在 2D 画布上草草划出目标姿态 → 用本项目已有的 IK 把骨骼解到草图关节点位 = 「草图捕姿」。这是新交互立项级别的方向，本次只登记，不展开。

### 6. 联动拖拽的躯干权重弯 ——
- 拖 root/腰/胸时按 (1-t)^1.35、sin(πt)、线性 t 三种权重弯折 torsoPath，是没有骨骼系统时的轻量拟合。本项目有真 FK/IK，编辑拖拽应走自家求解，借它反而降级。仅作差异记录。

### 7. 弧长小算法 ——
- `getPointAtDistance`（沿折线弧长取点、超尾外推）+ `splitChainAtRatio`（按弧长比例切链）+ `strokeLength`：几十行的通用几何小函数。本项目在链、路径、堆叠切片等处都有同类需求，遇到时优先想起这套写法（自己实现同等简单，借的是思路与边界处理）。

### 8. 衣服比例（袖/裤分段） ——
- clothingRatios：四肢根部段按比例换成躯干色，模拟袖子/裤腿长度。本项目服装拆分走骨骼 ID 掩码（3D 件）；对 2D 手绘件的「按肢长比例切袖长/裤长」若将来要做，它的切分点位算法（弧长比例 + 关节吸附）可参考。低优先。

### 9. 空气透视（按层深雾化） ——
- 按肢体图层深度把颜色向雾色插值褪色（默认强度 0.35），廉价造纵深。本项目运行时有真实深度与画序；若想给 2D 场景加「远景褪色」氛围，这是一个现成的参数化做法（深度→雾色混合率），可登记为图案/后期方向的灵感，不单独立项。

### 10. 比例蓝图的数据形态与 A-pose 编辑器 ——
- 「一份比例数据 + 一个在 A-pose 人偶上拖关节改比例的可视化编辑器 + JSON 导入导出」这套形态，和本项目模式库条目（版本化数据 + 面板管理）天然合拍。若第 3 项的比例垫图要做成可调的（不同头身比预设：写实 7.5 头身/Q 版 3 头身等），编辑器形态照此设计即可。

### 11. 侧面模式 ——
- 它的「侧面」是把肩/髋横向间距压到 0.2 倍的 2D 假透视，与本项目真 3D/八方向体系不在一个层级。仅作差异记录（也提醒：它的 README 宣称「透视」，实际只有这一招，引用其宣传语时要打折）。

### 12. 背景参考图垫图 ——
- 它支持拖入背景图描摹（缩放/透明度/适配）。本项目 PixelCanvas 已有同等功能（参考图垫底 + 不透明度），功能对齐确认，不需要动作。

### 13. 笔触吸附与热区 ——
- 起笔点落入肩/髋关节点热区即吸附生成肢体（findAttachmentPoint），是笔触输入的关键手势细节。若做第 2 项（画火柴人建角）或第 5 项（草图捕姿），这套吸附判定直接参考。

## 四、总判定与建议顺序

- **值得做的**：① 无精灵人偶兜底（第 1+6 项，编辑器渲染一档，半径公式现成、自家 jointWidth 可喂）；② 比例常数表 + 标准比例垫图（第 3+10 项，数据级成本）。
- **值得立项再议的**：③ 笔触建角向导（第 2+13 项，新入口，量级最大）；④ 草图捕姿（第 5 项，依赖 IK 已有能力，交互新设计）。
- **明确不借的**：五官对位（它没有）、权重弯拖拽（自家更强）、侧面假透视（层级不对）。
- 对方成熟度提醒：一天 5 个提交的原型、无测试、文档与代码多处不一致（版本号三处互斥、快捷键表与实现不符）；借鉴对象是它的**数据与点子**，不是它的代码质量背书。
