# 精灵堆叠（sprite stacking）3D 导入方式 — 开题讨论

本线讨论现行 3D 导入之外的另一条路：不把模型烘成方向平面图，而是
切成一摞水平截面图，靠堆叠呈现体积与连续转面。本 PR 只讨论与定
验证方案，不写产品实现。

## 现行方式盘点

- 两条烘焙路：单烘（每个方向一张代表图）与六部件（6 部件 × 8 方向
  × 颜色/ID 两遍共 96 遍 3D 渲染，再用 ID 图把部件大图 2D 拆分成
  骨骼级精灵）。调拆分参数只重跑 2D 步，改几何要重跑 96 遍。
- 方向是离散的：variantIndex 0..7 共 8 个方向加镜像，转面就是换图，
  方向之间没有中间姿态。
- 姿态层已经是真 3D：Socket 存静态 3D 偏移（offset3D），Transform
  存动态姿态（angle/tilt 两角制、真 3D FK/IK、透视缩短通道）。但部
  件本身仍是一张平面图——3D 姿态只能搬动、旋转、缩短这张平面，部
  件绕自身竖轴转面时没有像素来源。
- 代价结构：像素量约为部件数 × 方向数；每个方向的像素互相独立，
  一个方向改了，其余方向不自动跟随。

## 精灵堆叠的机制

- 烘焙端：把模型（或部件）沿高度切成 N 层，每层一张水平截面图
  （自下而上编号），另记每层的锚点（截面中心在部件本地系的位置）。
- 呈现端：从底到顶逐层绘制，第 i 层叠加层间偏移；整摞的朝向由
  同一个 3D 朝向驱动：
  - 绕竖轴转（yaw）：每层图绕锚点同角做 2D 旋转，层间偏移不变，
    整摞原地转面，角度连续，不靠换图。
  - 俯仰/倾斜（pitch/tilt）：层间偏移按倾斜方向逐层累加（剪切），
    摞体随之倾倒。
- 像素来源只有一摞截面，这是它与方向烘焙的根本区别。

## 与现行管线的接点

- 烘焙器可复用：现行 PMX 渲染器的相机、材质、调色板量化都是现成
  的；切片相当于俯视正交相机加按高度推进的裁剪面逐层渲染。产物
  仍是精灵，可进精灵管理（一摞一个文件夹，出生信息记层序）。
- 姿态现成：部件的 3D 朝向已有完整数据（worldFrame、angle/tilt、
  透视缩短），堆叠呈现消费的正是同一份朝向，不需要新姿态系统。
- 画序：摞内自下而上固定序；摞与摞之间仍走现行深度/zIndex 排序。

## 候选方向（只列说法）

- 说法甲：整模型一摞。整个角色切成一摞，不进木偶层级，部件动画
  不参与；适合先验证机制与观感。
- 说法乙：按部件各一摞。粒度同现行六部件拆分，部件仍挂 socket
  受骨骼与姿态驱动，部件内的体积与转面由堆叠承担。
- 说法丙：混合。大体积部件（躯干、头）走堆叠，细长部件（手臂、
  手指链）仍走现行平面烘焙。

## 待拍板的问题

1. 切片粒度：甲 / 乙 / 丙。
2. yaw 的像素来源，三选一：运行时逐层 2D 旋转（角度连续，但每层
   像素被旋转重采样，像素画的锐利度受影响）；预烘 K 个 yaw 角的
   摞（像素干净，存储与烘焙量乘 K）；不旋转图、只用层间偏移表达
   朝向（yaw 表达力最弱）。
3. 层厚与层数：一层多厚（按像素定厚还是按模型高度等分）、层数
   上限。这一项直接决定像素总量（约等于每层截面面积之和）与每
   帧绘制量（部件数 × 层数张图）。
4. 数据落点：切片序列是「一组普通精灵加约定」，还是新结构（部
   件挂 stack 数据：层图列表、层距、锚点）；精灵标记（marks）与
   plug 在一摞图上怎么定义。
5. 取舍边界：堆叠表达不了的情况（部件绕横轴大角度翻转时截面语
   义崩坏、跨摞遮挡不准）接受到什么程度，是否因此只用于特定部
   件或道具。
6. 验证对象与判据：先拿哪个模型试烘一摞（简单几何体或道具 →
   Xbot → reze 的顺序？）；观感判据是什么（转面连续性、层间错
   位、像素锐利度）。

## 本线范围

- 本 PR：开题与讨论；拍板后在本线追加最小验证（烘一摞 + 堆叠呈
  现探针），验证结论回写本文档。
- 不动现行烘焙与渲染的产品代码。
