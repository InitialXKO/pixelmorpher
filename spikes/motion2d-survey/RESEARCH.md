# Motion2D / 2dimg2motion 调研：与本项目的功能对照

日期：2026-10-28。方法：两源均第一手读取（motion2donline.com 首页全文、GitHub 仓库页与 README 全文），本项目一侧逐项回源码核对落点。

## 〇、对象澄清（先纠正题目里的一个误会）

- **github.com/2dimg2motion 这个账号不存在**（直开抓取失败、多轮搜索无此账号页）。实际对象是个人仓库 **`WU-HAOTIAN34/2dimg2motion`**（236 star、MIT、2026-06 建仓）：一个给 Codex / Claude Code 等代理用的 **Agent Skill**，不是软件产品。下文以该仓库为准。
- **motion2donline.com 是产品「Motion2D」的官网**，目前实质只有一个页面（首页）；`/pricing`、`/features`、`/blog`、`/help` 全部 404，收费模式全站未见。功能信息全部来自首页。
- 两者无证据表明是同一团队：Motion2D 的拆分靠其自有「SeeThrough 本站拆分服务」；2dimg2motion 是独立的开源 Skill。不要把两家混为一谈。

## 一、两者各是什么（范式先分清）

**Motion2D 与本项目同范式**：原画拆部件 → 绑骨骼 → 挑动作修帧 → 多格式导出。差别主要在三处：它把「单图 AI 拆分」做成一等公民入口、绑定走「2D 图上拖骨点位 + 一键绑定」的轻量路线、导出格式铺得很宽（含桌宠、Godot、Spine 交换包）。

**2dimg2motion 是异范式**：没有骨骼、没有编辑器。它是一套提示词 + 脚本的工作流，让图像模型**整角色重绘**关键姿势（02/05/08/11 四张），再参照生成中间帧凑满 14 帧，脚本只做抠像、归一化、打包、校验。交付物是逐帧重绘的序列帧 / spritesheet，动画本身不可再编辑、不可换装、不可驱动。它解决的问题是「没有美术管线时快速量产一次性动作帧」，与本项目「一份资产反复驱动」是互补关系而非竞争关系。

## 二、Motion2D 逐项对照

状态口径：**已支持** = 本项目有对应功能；**变相支持** = 目标达成但机制不同（写明差在哪）；**不支持** = 确无此物。

| # | Motion2D 功能 | 本项目状态 | 依据 / 差异 |
|---|---|---|---|
| 1 | PSD 直读、按图层导入成部件 | **不支持** | 源码无 PSD 解析。相邻能力：Aseprite `.ase` 解析、PNG/精灵导入、Spine 导入、Live2D 导入、3D 模型（PMX/GLB）烘焙导入——唯独缺 PSD |
| 2 | PNG 部件导入与摆位 | 已支持 | 精灵库 + 服装件挂载 + 手动摆位是本项目日常路径 |
| 3 | AI 拆分：单张原画 → 分层部件（SeeThrough） | **变相支持一部分** | 有 SAM 分割、按骨骼 ID 掩码拆分、运动分析拆分（帧间位移聚类）、Telea 补洞；但没有「单图语义分层 + 被遮挡部位补全」的一体管线——本项目的拆分都要求骨骼/3D/视频等额外信息源，纯单图进不来 |
| 4 | 手动绑骨：图上拖骨骼点位、确认后一键绑定 | **变相支持** | 骨骼来源是 3D 烘焙自动生成 / 笔触建角 / 手动编辑节点；绑定模型是像素归属节点 + 蒙皮弯曲，不是权重刷。缺的是「在一张 2D 图上从零拖点摆骨 → 一键绑」这条专门向导（零件大多已有：笔触建角、草图捕姿、节点编辑） |
| 5 | 所有步骤 AI 辅助 | 大部分不支持 | 仅 SAM 分割一处属 AI 辅助；其余步骤无生成式 AI 参与 |
| 6 | 挑动作 | **变相支持** | 有程序化表演、预设、状态机/行为树编排（对象是「表演」）；但没有「成品动作库一键套到任意角色」这种货架式动作包 |
| 7 | 修帧（边预览边逐帧精修） | 已支持 | 时间轴 + 关键帧编辑 + 洋葱皮 |
| 8 | 加特效 | 已支持 | 蓝图特效、图案、粒子、发光、像素链，深度远超对方（对方首页未列特效种类） |
| 9 | 实时预览 | 已支持 | 画布实时渲染 + 程序化预览面板 |
| 10 | 表情工作台资产 `.facerig` | **变相支持** | 有五官点位参数（头部节点）、转面、Live2D 导出含表情面/keyforms；但没有独立的表情资产文件与专门工作台 |
| 11 | 导出 GIF / MP4 | 已支持 | ExportDialog：GIF（gif.js）、视频 webm/mp4 均有 |
| 12 | 导出 PNG 序列 ZIP | 已支持 | ExportDialog PNG 序列导出 |
| 13 | 导出精灵图 ZIP | 已支持 | spritesheet 导出（横/竖排） |
| 14 | 网页播放器 ZIP | 已支持且更强 | proc-runtime 运行时包：自带状态机/行为编排、触发、钳制锚定运行时；对方为单纯播放器（按其导出列表推断，细节未见） |
| 15 | 动态闪卡 ZIP | **变相支持** | 运行时包可承载同样内容；无专门「闪卡」打包名目，价值低 |
| 16 | 桌宠 / 桌面卡片 `.m2dpack` | **不支持** | 无桌面端打包与桌宠壳 |
| 17 | Godot 4 运行包 / 可编辑动作 ZIP | **不支持** | 无 Godot 端播放器或数据交换 |
| 18 | Spine JSON 交换包 ZIP（导出） | **不支持** | 本项目只有 Spine **导入**（JSON+atlas+PNG → Character），没有反向导出 |
| 19 | 可编辑工程 `.dchar` | 已支持 | 本项目自有工程格式与 project 导出，对应物齐全（另有 Lottie、Live2D 导出，对方未见） |
| 20 | 分层 PSD 素材 ZIP（导出） | **不支持** | 与 #1 同缺 PSD 编解码；导出方向价值低于导入 |
| 21 | 首页 WASD 可操作示例角色 | **变相支持** | 运行时包支持触发与状态机驱动的可交互角色；编辑器内无此演示位，属展示层而非能力缺口 |

## 三、2dimg2motion 逐项对照

| # | 机制 | 本项目状态 | 说明 |
|---|---|---|---|
| 1 | 整角色关键姿势重绘（图像模型画关键帧+中间帧） | **不支持，范式不同** | 本项目驱动原画像素、从不重绘。这条路线产出的是一次性帧动画，接入方式只能是「当素材导入」，见 §四 G |
| 2 | 身份锁（提示词固定角色不变量防漂移） | **变相支持（由构造保证）** | 同一套像素被骨骼驱动，不存在身份漂移，不需要锁 |
| 3 | 拓扑锁（活动肢/锚定肢/武器归属，防换手换肩） | **变相支持（由构造保证）** | 肢体与武器归属是骨骼结构数据，换手在结构上不可能发生。附带一提：它的「锚定肢」与本项目刚落地的钳制锚定同名不同物——它指生成时不动的那侧肢体，本项目指运行时冻结锚点 |
| 4 | 14 帧固定结构 + 1/2/2/2/1 中间帧插入计划 | 不适用 | 本项目关键帧自由、插值/程序化补间，与固定帧式结构是两种时间模型 |
| 5 | 8 类动作节拍表（idle/walk/attack/block/hit/death/born/skill，各有 anticipation→contact→follow-through 等节拍序） | **变相支持一部分** | 程序化动画模式里编码了部分动作规律，但没有「按动作类型的节拍模板」这一层现成资产。节拍表本身是可直接借鉴的知识，见 §四 F |
| 6 | 基准图标准化（裁透明边、主体缩放至 ~360px、留动作边距） | **变相支持一部分** | 导入有紧包围盒+2px padding 的裁剪口径；但没有「为后续动作预留边距」的标准化预处理（它的边距是防动作出界，本项目的 padding 只防裁切） |
| 7 | chroma-key 纯色底生成 + 本地去背 | 不支持（当前不需要） | 本项目素材自带透明通道；只有接入生成式素材（§四 G）时才成为必需件 |
| 8 | 确定性交付校验（帧数/命名/首尾帧字节一致/基线稳定 + contact-sheet 目检） | **变相支持一部分** | 本项目工程文化里有大量探针校验，但产品内没有面向序列帧交付的校验与审查图导出 |
| 9 | `/img2mo-learn`：从参考视频/失败案例沉淀项目知识库供下次生成 | 不支持 | 这是给 AI 代理工作流的机制，与编辑器产品形态无关，**不建议引入**，仅记录 |
| 10 | 输出 spritesheet/GIF/序列帧供 Godot/Unity/Cocos | 已支持 | 格式层通用，本项目导出齐全（见 §二 11–13） |

## 四、可加入清单（按价值/代价排序，待裁决）

| 项 | 内容 | 价值与落点 | 代价估计 |
|---|---|---|---|
| **A. PSD 图层导入** | 解析 PSD，图层直接成部件/精灵，补上 Motion2D 的起点格式 | 本项目导入器家族（Aseprite/Spine/Live2D/3D）唯独缺 PSD，而 PSD 是原画师最常见的交付格式；落入现有导入管线尾端、数据模型零改动 | 中：PSD 格式解析（图层/混合模式只取像素与层序即可，不必全规格） |
| **B. 单图 AI 分层拆分导入** | 单张原画 → 语义分层部件（SeeThrough 式），接现有拆分/补洞零件 | 两家共同指向的趋势，也是本项目「纯 2D 单图」入口的唯一缺口；已有 SAM、Telea 补洞、部件管线可复用，缺的是分层模型本身 | 大：依赖外部模型或服务。SeeThrough 是否开源/可自托管**未核实**（其官网只称「本站拆分服务」），立项时先核这一条再定接服务还是本地模型 |
| **C. Spine JSON 导出** | Character → Spine JSON+atlas，与已有 Spine 导入成对 | 导入器已摸清 Spine 数据模型，反向映射成本可控；打通与 Spine 生态的双向交换 | 中：骨骼/槽位/附件/动画曲线映射，网格权重部分可能要降级并点名 |
| **D. 桌宠打包** | 运行时包 + 桌面壳导出桌宠 | 运行时包与行为宿主（状态机/触发）已有底子，桌宠是 Motion2D 明牌的差异化出口 | 中：缺桌面壳（透明窗/置顶/点击穿透）与打包格式，动画侧零新工作 |
| **E. Godot 运行包** | proc-runtime 数据的 Godot 端播放器 | 对方明牌出口之一；本项目运行时数据格式是引擎无关的，理论上可移植 | 大：等于在 Godot 里重写一遍播放器（含图案/粒子/钳制锚定的子集取舍），建议先只做数据交换（可编辑动作）试水再评估 |
| **F. 动作节拍预设库** | 借 2dimg2motion 的 8 类节拍表，做成程序化表演/关键帧生成的节拍模板 | 小而实：节拍（预备→接触→跟随→回收）是现成的动画知识，本项目程序化一侧正缺这层模板；对方仓库 MIT，节拍表可直接参考改写 | 小：数据 + 预设接线，无新机制 |
| **G. AI 重绘序列帧素材接入** | 把 2dimg2motion 式产物（或任何逐帧重绘序列）作为一种帧动画素材接进工程：序列帧资产 + 基线对齐 + 交付校验 + contact-sheet 审查图（附带 chroma 去背） | 承认异范式的产能价值：一次性动作（死亡、出生、技能大招）用重绘帧、本项目负责其余可驱动部分，两条管线在工程里会合 | 中：需要一种「帧动画素材」的承载位（现无此资产类型，是本项主要设计点）；校验脚本可参考对方 validate 逻辑（MIT） |

**不建议加入**：分层 PSD 导出（导入的附带品，单独立项价值低）、动态闪卡打包（运行时包已覆盖）、`.facerig` 独立格式（表情能力已有承载，缺的是工作台深度而非文件格式）、img2mo-learn 知识库机制（服务对象是 AI 代理、不是编辑器用户）。
